# P1 独立模拟与专题能力首版

本版按 #43 / APS-BL-001 v0.3 FR041–043、AC30 的已批准基础范围提供独立预测试算。不是自动预测冲减、补库算法或全部专题验收。实施依据为 #43 comment-6560049991，CR 归属依据为 #36 comment-6560047620。原基线不改写。

在现有订单表维护“预测”，在 `p1DemandSources` 维护订单/配置/来源编号/来源版本/来源说明，在 `p1Profiles` 维护配置编号/版本/来源说明/显式策略。三表可使用既有 CSV 预览确认、跨表编辑、查询及导出。来源只引用预测，一条需求只能归一个场景。未选场景时保留正式订单默认；选场景后仅其有效预测进入计算，不能混选正式订单，不推定关联订单、不自动叠加或去重。

`selection.p1ProfileId` 是显式场景入口。新运行冻结完整原输入、输入 SHA256、配置/profile 版本、需求来源及所选数量/单位。仅隔离的 executionData 副本把所选预测适配为既有排程内核的订单表示；原输入仍为预测，conditions.p1Topic 保留原类型与来源，所有 API/Worker/复核沿同一合同检查。新运行不会写入正式订单数量、库存预占或执行事实。保存的任务查询与 CSV 显示“独立预测模拟”、专题及来源版本。历史运行不随当前编辑变化。试算副本及重算沿原场景，主管提交/确认/内部发布在服务端明确拒绝。

复用当前已配置路线、设备/工装/人员/物料及有效硬约束和排序。其具体检查范围按原引擎逐项显示，未检查不算通过；本版不新增可选路线算法。P1 仅接受既有顺序路线，新增分支/汇合/返工显式拒绝。B16 如被显式选择仍采用其配置及共享资源合同，不因 P1 放宽硬约束。

浏览器与服务端共用 `src/lib/p1-topics-contract.mjs`。每项策略显式为 ENABLED 或 NOT_ENABLED；无法通过新增字段声明计算支持。预测冲减、目标库存补库、新权重保留 NOT_ENABLED；分支返工、配方选择、蒸汽/制冷/周转器具等新资源 UNSUPPORTED。保存启用请求、冻结运行和伪造 Worker 条件均拒绝。`GET /p1/capabilities` 返回相同能力声明。PM 6559540976 是待确认提案，不是生效公式。B02 effective=false 不变。

可替换小样例由 `node --experimental-strip-types qa/p1-topics-sample.mjs <输出目录>` 生成；同目录三步说明。完整构建与 API/Worker 验证仅在获准串行窗口、官方 disposable validation 中运行，不修改 0afa/18302、Test 预览目录、绑定、dist、state，不新建应用或常驻候选，不发布。
