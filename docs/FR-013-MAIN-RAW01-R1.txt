Problem and repair
The old editor compared LF-normalized textarea values, treated the first-to-last changed region as all-new text and converted every newline in it to the first source style. Two separated corrections therefore silently changed untouched quoted contents between them. The independently reported input, expected output, observed corrupted output and persisted name were read directly from APS-Test's report/archive. GitHub issue24 was freshly read, remains open, and the remote branch matched the integrated FR014/015 checkpoint before repair.

editCsvDraft now retains normalized-to-source UTF-16 boundary offsets and maps each separate equal span back to the original raw substring. A two-level bidirectional Myers alignment anchors complete unchanged visible lines, then refines each changed gap by character. Line anchors avoid aligning an old line's raw newline with a newly pasted line. The frontiers use linear space. No fixture recognition, CSV-field substitution, new dependency, Unicode normalization, or inferred file-wide newline style is used. New text uses the textarea value verbatim (new browser-entered newline is LF); unchanged CR/LF/CRLF and intermediate fields remain exact. The old unit assertion that imposed CRLF on a newly inserted LF was updated to this explicit no-guessing contract.

Only existing production src/lib/csv-draft.mjs changes. Its original unit test changes one inserted-newline expectation. All other 133 current src/server/public files are byte-identical to the integrated parent; broader source/preservation manifests and original Test-script hashes are supplied. App, FR014/015 query/editor features, API, token/current-state checks, confirmed-history protection and FR027/035/036/038 code are preserved.
