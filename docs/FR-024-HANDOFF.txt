Implementation
src/lib/result-assessment.mjs saves FR024-v1 report with every new synchronous or asynchronous canonical plan. Reports use frozen execution inputs and saved actual tasks, not current edited data. Status scheduled means found arrangements within the saved check scope; partial-unplanned includes missing expected task operations or reported issues. Existing worker queued/running/completed/partial/timed_out/failed/cancelled terminal state authority remains. Public run resultState maps to scheduled / partial-unplanned / time-limit-no-result / calculation-failure / user-cancellation, plus queued/running/unknown. Global feasibility stays unknown, including timeout. Old plans without reports explicitly stay unknown and are not reconstructed from current data.

Missing operations are projected from original selected order routes and explicit production-batch identities. They are not inserted into saved plan.tasks, resource reservations or Gantt. When batch generation is blocked before batch identities exist, the report uses order-operation entries and order remaining quantity, not an invented production-batch count. Unlinked causes stay UNKNOWN_TASK_CAUSE separately from observed blockers, data repair, blocked predecessor and unresolved policy. Global/order issues remain preserved independently; no text-based guess assigns a global issue to a specific task. Group under-min reasons now identify every actual member-operation and preserve load/min/max. Known batch-configuration failures retain explicit original order context.

Failure context is captured at the scheduler decision: candidate minute/date, required continuous duration, assigned machine, configured horizon and resource declarations. Per-task report keeps actual task start/end separately from candidate dates. Input references retain frozen original order, route, time, dependencies, machine, calendar, downtime, explicit claims/tool/space, relevant personnel groups and material/BOM/lot/supply/use/delay rows. Material demand rows preserve exact rational shortage, FEFO allocations, feed time, version, units, blockedReason and committed status. Conditional supply and simulated quality provenance are retained, never physical goods or true quality assertions. Unsupported/unresolved/unknown are separately visible.

Applicable suggestions are selected from saved concrete blockers: repair data/references, delay to valid declared windows/usable supply, edit only relevant simulated personnel/tool/space capacity, or edit permissible demand/split/compatible batching. Predecessor blockers ask to resolve preceding work rather than bypass sequence. All suggestions carry guaranteed:false and requiresNewRun:true; no proposal guarantees feasibility or automatically changes data. No procurement, execution, release or downstream workflow is fabricated.

ResultPanel shows saved report, task/quantity/date/resource/shortage evidence, suggestions, unknowns and limits. Scheduled task buttons select the actual saved Gantt task. Unscheduled entries have no fake Gantt link. Input buttons open the exact saved historical source table and row through DataQueries. Existing RunPanel opens saved results/frozen inputs, shows distinct run-state labels, and adds permission-gated run CSV export, including no-result terminal states. Plan export includes FR024 saved report and original FR023 conditional completion/delivery evidence. Read/write/export roles, CSRF, trusted actor, required reason and atomic audit/persistence paths remain authoritative. No new messaging endpoint or bridge alternative.
