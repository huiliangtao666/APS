# APS R1 原型测试接口与字段约定

**版本：** FR-002 增量（延续 FR-001 / R2.1 preview slice），基于 APS v0.3 评审稿与配套测试数据 v0.3。  
**对象：** APS-Test 测试设计 / APS-Design 评审。  
**当前成熟度：** 可预览原型；以下均是待测试行为约定，不代表产品 UAT 已通过。

## 1. 输入和可追溯基线

源说明书定位：第 2.2 章首期组合 F1+F3 / C0 / D1 / L1；第 5 章 BP-01 至 BP-05；第 6 章 FR-013 至 FR-019、FR-025/026、FR-033/034/035；第 7 章 BR-01/02/03/15/18；第 8 章 DT-09/11/13/14；第 10 章 PG-01/02/03/04/05；第 12 章 R1；第 14 章 AC-01/02/04。数据基线 `UAT-01_最小排程与可视核对完整流程/本阶段导入数据`。

示例的产品 HC40/HC60、A/B 订单、设备、工时和路线全为模拟数据。说明书及测试包均注明虚构火腿肠业务，不构成真实配方、生产工艺、设备能力或食品安全参数。

FR-001 产线/工位/资源归属沿用可编辑的订单与设备资源表：订单 `产线编号` 定义本次订单线；设备资源 `产线编号` 定义机器/资源所属线，`工序编号` 表示其适用工位/工序。该原型当前没有独立产线主数据或工位主数据表。单线下可以配置多个工序以及多个同工序设备；设备编号是独立资源，不是产线编号。

### FR-002 产品、物料与单位配置

产品表字段按 v0.3 DT-02/测试包 07 表；物料表字段按 DT-03/测试包 08 表。数据页可编辑、新增、删除、导入/导出两类表。HC40/HC60 和 LEAN/FAT/WATER/PREMIX/BAG 示例沿用 UAT-01 虚构数据，仅作为有效引用夹具。

点击计算前执行主数据校验：产品及物料编号/必填字段、编号重复、产品净重/每袋支数/总收率/交付等待数值、订单和工艺路线引用产品存在、工序物料依赖引用物料存在。出现问题时返回 0 个任务并显示定位信息。产品名称不参与规则判断。新增或删除主数据后，引用关系会在下一次计算时重新检查。

本切片只保存 kg、支/袋等配置字段，不据此转换订单数量、工时、包装量或 BOM 用量。v0.3 BR-18 将展示/计算精度、支/袋/箱取整和误差范围列为待确认项；精度、换算方向、换算链、取整时点及误差处理均未定，不能把样例净重或每袋支数当作已确认换算语义。BOM、库存批次、物料可用性和物料需求计算仍未实现。单位字段作为配置文本保存；数值只做必填、数值/正负基础校验，不按字段推导量纲或跨单位兼容性。

可复现自动用例（应用容器内执行 `npm test`）：`src/lib/master-data.test.mjs` 验证有效配置、必填/重复/数值错误、订单/路线产品引用、物料依赖引用，以及单位值仅记录而不触发换算。可手工在产品表删除 HC40 后点击计算，订单 A 应提示产品引用错误且不生成任务；在物料表删除 LEAN 并在物料依赖中引用 LEAN，应提示物料引用错误且不生成任务；恢复有效主数据后可继续进入既有路线/资源检查。

### 任务与计划对象

任务 JSON 字段：`id`, `orderId`, `productId`, `operation`, `label`, `machine`, `start`, `end`, `duration`, `predecessor`, `source`。主键规则为 `{订单编号}-{工序编号}`；分钟基准 0 = `2026-11-02 08:00:00+08:00`（测试包统一起点）；时间区间为 `[start,end)`，右端点等于下一任务开始时不冲突。方案字段：`id`, `name`, `createdAt`, `tasks`, `findings`, `rules`, `inputVersion`。快照 API：`GET /api/plans`、`POST /api/plans`。输入数据现在仅保存在浏览器 localStorage，不包含服务端方案输入快照。

## 3. 计算及问题行为契约

1. P0 每次排程只接受一条产线。订单必须有产线编号且订单间只能出现一条；缺失时生成 `INPUT / LINE_MISSING`，订单多线时生成 `SCOPE / MULTI_LINE`。每条已登记设备资源必须有产线归属，缺失时生成 `INPUT / RESOURCE_LINE_MISSING`；资源配置引用多条线时生成 `SCOPE / RESOURCE_MULTI_LINE`；资源线与唯一订单线不一致时生成 `SCOPE / RESOURCE_LINE_MISMATCH`。任一产线问题都阻止计算并返回 0 个任务。产线编号不限定为 L01；UAT-01 样例是 L01。空白设备行不作为已登记资源。
2. 订单按“优先顺序”数值升序；路线按前序引用拓扑排序，互不依赖的工序保持 CSV 行顺序。
3. 每个订单/工序必须有匹配时间记录及订单+工序+资源类型“设备”的依赖，设备必须存在且设备工序匹配；不自动替用户选兼容设备。
4. `固定分钟` 是唯一生效的工时表达。缺少路线、固定工时、匹配前序或有效设备时生成输入问题，不计算缺少的任务。路线工序编号重复、前序引用缺失或循环时，按订单/产品列出具体配置问题并跳过该产品，不静默忽略。
5. 后序最早开始 = 前序完成；同一设备以贪心向后寻找空隙，避免 `[start,end)` 资源冲突。
6. R2.1 日历：从设备 `日历编号` 关联到工厂工作日历；编号为空时暂按唯一配置日历继承。任务时长必须整体落在一个 `是否工作=是` 的连续窗口中；该设备停机区间再从窗口扣除。工厂没有工作窗口时，不因机器空闲而排任务。停机/窗口按半开区间处理，端点相邻合法。
7. 计划完成后扫描机器重叠及前序关系；问题关联任务 ID，点击后甘特高亮任务。日历不可用的工序不生成任务，问题说明未排原因。
8. 当前不计算目标最优性、物料可行性、交期准时、全订单覆盖、资源负荷或任何未启用/未实现规则状态。页面必须保留这种限制提示。
9. 保存的方案快照不随之后的输入表编辑而覆盖；但没有完整历史输入快照/差异功能，因此不能声称可完全复现旧方案。

## 5. R2.1 日历阶段测试约定（APS-Test）

本节针对当前 APS-Dev R2.1 预览切片，供 APS-Test 设计用例；这不是测试结果，也不表示 AC-05/UAT-02 已通过。入口在 APS-Dev Workbench 的 APS R1 单线排程预览，页面版本标记 `R2.1 阶段切片`。测试输入位于 `sample-data/UAT-02/`（02/03/04/10/11/12/16/17 八张 CSV）；数据页逐表导入/编辑/新增/删除，工作台点击“计算排程”后核对问题定位与任务明细。

时间基准为分钟：0 = `2026-11-02 08:00:00+08:00`，显示时区 `Asia/Shanghai`；任务、日历窗口和停机使用半开区间 `[start,end)`。说明书 `AC-05 工作日历` 的场景是“设备 08:30–09:00 停机；任务需要连续30分钟”，预期“任务不跨停机；停机和顺延原因可见，不偷偷拆开任务”。UAT-02 使用 FC01 工作区间 `0–600`、MIX02 停机 `0–15`；边界明确为任务恰好从 08:15 开始合法、08:14 开始不合法。参考安排为 A-MIX 0–30、A-FILL 30–60、B-MIX 15–45、B-FILL 45–75，期望状态 FEASIBLE；参考安排不是唯一解。

| ID | 设置与操作 | 预期观察（供 APS-Test 验证） |
|---|---|---|
| R2.1-01 / UAT-02 | 导入 UAT-02 阶段 CSV，FC01 工作 0–600，MIX02 停机 0–15，运行排程 | A-MIX 可 0–30；B-MIX 不早于 15；B-FILL 不早于其前序完成。任务均满足工厂窗口/设备停机；不要求精确复制参考排法。 |
| R2.1-02 / 边界 | 用两道同机工序构成小夹具：前序工时14分钟，后序工时1分钟；为设备配置停机 `[14,15)` | 后序最早时刻14与停机 `[14,15)` 相交，应顺延至15；移除停机后后序可在14开始。另用 `[0,15)` 验证任务可从15开始。 |
| R2.1-03 / AC-05 | 将停机设为 30–60（08:30–09:00），并用前序把该设备上一项需连续30分钟的工序最早时刻设为分钟15（08:15） | 该任务不得跨入停机区间，应顺延至分钟60（09:00）；若后续连续窗口不足30分钟，则任务保持未排并说明原因；不得拆成两段。 |
| R2.1-04 / 工厂停工 | 将唯一工作日历行改为 `是否工作=否`，设备空闲，运行计算 | 不得仅因设备空闲而排任务；任务不生成，显示工厂无工作窗口/未排原因。 |
| R2.1-05 / 继承 | 多台设备关联 FC01，只给一台设备配置停机 | 所有设备继承 FC01；仅配置停机的设备可用区间缩短，其他设备仍可在工厂窗口排程。 |
| R2.1-06 / 端点与顺序 | 检查任务恰好在窗口结束时完成；再核对前后序任务 | `[start,end)` 右端点可等于窗口结束；后序不可早于前序完成；没有隐式跨窗口续排。 |

字段/模型约定：02 表每行表示一个绝对分钟窗口（不是循环周历模板）；`是否工作=是` 的行定义可排窗口；同一日历中 `否` 行会从工作窗口中扣除，形成休息/停工间隔。设备 `日历编号` 关联工作日历，当前没有独立设备工作时段覆盖；空编号暂按唯一配置日历继承。04 表按设备编号关联并扣减区间。无有效工作窗口、无连续可容纳工时的窗口时任务不进入任务明细，产生 `UNPLANNED / CALENDAR`。成功顺延的任务在来源栏说明工厂窗口或停机顺延原因。设备停机只缩短该设备窗口，不改变工厂日历，也不影响其他设备。

明确待决：有效日期/周循环、节假日优先级、跨日窗口；跨班策略；可中断工序及最小连续段/中断恢复；开始/结束所需人员组、技能和占用边界。原型目前把任务约束为完整落在单个连续窗口、不拆分；这只是本阶段明确限制，未视为业务决策。R2.2 工装、R2.3/R2.4 人员容量均不参与计算，辅助表字段不可作为其通过依据。

## 6. 测试时的限制和建议

### FR-009 订单与需求数据增量

订单表在原 v0.3 `合格需求kg` 基础上迁移为 `合格需求` + `数量单位`，保留 `要求可交付分钟`（既有分钟轴接口）并增加 `是否允许拆分`、`需求类型`（正式订单/预测）和 `订单状态`（有效/已取消）。旧版浏览器数据会读入为 kg、不可拆分、正式订单、有效；CSV 导入使用新字段契约。单次 P0 排程继续限制为单线。校验订单编号唯一、必填字段、数量正数、优先级非负数及拆分枚举。
