Delivered behavior and modes
Default/omitted mode remains supported, preserving calendar/downtime windows, configured personnel requirements even if LABOR flag is off, and explicit expected-supply availability. A constrained or partial supported run is never retried in minimal mode. Full business/all-rule feasibility is still not implemented and is never claimed.
Only explicit selection.mode=minimal-r1 activates original R1 scope. It uses the SAME constructive scheduler with continuously available assigned machines, original fixed positive durations, original route predecessor references, stable source ordering among independent steps, current chosen start/end/order priorities and unique same-line formal active orders. Same-machine intervals cannot overlap; successors start at/after predecessor end. Intervals are half-open, so adjacent endpoints are valid. Fractional fixed durations remain exact in stored numeric task times. Independent machines may run concurrently. No implicit machine substitution, duration shortening, truncation, route dependency removal or automatic mode downgrade.
Minimal mode does not use factory calendar/working-window/downtime restrictions, personnel allocation, expected-supply waiting or material feasibility. It records all of those as unchecked, along with tooling/molds, BOM/inventory/material allocation, capacity/batching, programs, maximum waiting/storage, cleaning, delivery/shelf-life, execution/confirmation and full speed/unit/rounding semantics. No material is reserved/consumed. A machine/precedence pass is explicitly not full business feasibility.
Canonical data saving and structural/reference validation remain unchanged. Minimal mode does not bypass corrupt input, invalid/unimplemented enabled rule configuration, missing fixed times, duplicate machine assignment, cycle checks, line scope, or necessary stored rule protection. Saved machine/calendar reference schema remains required by the integrated data contract, even though minimal execution ignores calendar availability. CALENDAR remains present/enabled in original and execution rule rows; its setting is explicitly inactive and labelled 本次最小模式未检查. This is an explicit calculation scope, not editing or silently disabling necessary stored rules. Only MACHINE/PRECEDENCE and any active SORT setting are adopted in minimal ruleSnapshot.
Complete tasks must finish within a chosen endMinute; a task outside it is unplanned and its dependent successor cannot silently run. Equality at end is accepted. No feasible result is promised by this greedy scheduler, and unplanned does not prove global infeasibility. Existing1000-attempt per-operation search bound remains. Omitted end on compatibility requests remains allowed; UI requests explicit end.
