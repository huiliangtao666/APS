## 三步小样例

1. 在独立应用环境打开“数据与 CSV”，批量预览并提交样例全部 CSV。样例为明确可替换 MOCK，不更改原上传文件或现有用户数据。`38_B16多线配置.csv`保存带版本/来源的产品适用、资源共享许可和订单选线；`39_B16逐线设备候选.csv`显式给出每个订单、工序及候选线的唯一设备。在数据页可以结构化编辑，也能用同一原生 CSV 接口导入、查询、导出。
2. 打开“排程工作台”，在“多线配置”选 `MOCK16`，保留已有支持模式及 MACHINE/PRECEDENCE/CALENDAR/MATERIAL/MOLD/LABOR，范围 0–600 分钟，发起真实 Worker 计算。A 自动选线，B 指定 L02。参考 A-MIX 0–30、A-FILL 30–60、B-MIX 90–120、B-FILL 120–150；不是唯一合法顺序。LEAN 初始162.5 + 09:30条件供给162.5，只够两单各162.5kg。
3. 在模拟数据查询选择方案任务，以“产线”筛选 L01/L02 或“多线汇总”。任务带实际所选产线及精确数量。保存、重开、独立复核、原生导出；原有提交/主管确认/退回流程保留，预计供给需明确承认条件。另一份配置改为指定线重新计算后，沿用方案比较，不改写旧计划。

生成可替换 CSV：在授权容器里运行
`node --experimental-strip-types qa/b16-application-sample.mjs /tmp/b16-sample`。
HTTP调用使用既有 `POST /inputs`、批导 preview/commit、`POST /runs`；本次选择为
`{"capability":"B16-multiline-v1","profileId":"MOCK16","startMinute":0,"endMinute":600,"priority":"优先顺序"}`。
未显式选择 capability 时继续执行原 P0 单线守卫。

## 计算和复核

自动候选只取产品允许且有完整设备映射的线，按显式列表顺序查找第一个完整可行候选；沿用现有任务排序和规则，不引入成本权重或宣称最优。最多128个组合，超限清楚拒绝并建议显式指定部分订单，不宣称全局无解。候选必须满足数量、交期、日历、设备、工装、人员、物料和适用的拆批/配对约束。

每个完整候选调用同一既有排程器，内部共用一个物料分配器及全厂资源占用账。同一设备ID、工装ID、人员组和物理人员池的容量不会按线复制。整个候选失败后任务/物料/资源提交账全部清空，诊断放在 rejectedCandidate；没有B02全局预占或实际库存写回。条件预计供给仍为条件。

跨线物理设备须在配置中显式增加 `machineScopes`，每项含 resourceId、factoryId、lineIds、allowCrossLine=true、capacity="1"；设备原归属和实际排程线均需在许可中。只有这条显式路径扩展日历复核；P0保持旧行为。原05/06身份/容量/来源及权限守卫保留，B16配置补充允许线；不会复制实体。B12生产批和完整加工冷却路线仍走原排程/独立复核，实现没有第二套算法。

独立复核按冻结profile、实际选线、显式设备映射、全部任务需求、数量和全厂账核对。启用的检查必须通过；未启用的拆批/最大等待保留not_checked，不算PASS。原输入产线保存原文，自动分配的产线独立写入lineAssignments、任务、比较和导出。

## 验证与运行边界

`qa/b16-application.test.mjs`覆盖原生CSV/API/真实Worker、保存读回/导出、跨秒重放及主管确认、自动替代、物料事务回滚、共享设备和工装/人员冲突、B12拆批、原05来源和产线查询。`qa/b16-application-ui.test.tsx`为React静态渲染检查；不是浏览器点击或用户UAT。

用官方 `app-exec.sh --validate --mode standalone` 在临时副本执行构建/自测，依赖复制为独立副本，不写线上dist/state，不启动持久候选。当前0afa/18302用户产品保持原版本，本实现没有可用的新用户URL；PM在明确运行资源和入口后安排部署/短smoke及用户验证。构建成功或回环API通过不等于已部署。

范围外：跨厂运输、新成本目标、任意混批、B02全局预占、DEC04–06新增应用、P1专题补库/D3。大Excel及原19全部场景沿旧固定SHA证据，本次只做新多线接缝影响检查。单线Excel仿真profile继续独立存在；B16小样例使用已批准的规范化CSV模型，不把Excel的单线仿真配置静默改成多线。
