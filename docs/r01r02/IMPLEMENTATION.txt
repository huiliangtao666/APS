Engineering decisions
Keep the existing whole-route grouping and personnel/physical pool contracts. Introduce
FR022-joint-v1 only on new supported runs. Each candidate clears all prior previews;
calendar, machine, declared tool/space, personnel and material must succeed at one start
before any allocation is committed. Every shift reruns the whole path. Frozen jointAttempts
records member task links, attempted starts, success/unscheduled/horizon and timing causes.
Existing result details and CSV now expose the trace, including completely unscheduled cases.
The 1000-candidate bound is explicitly search-not-found, never proof of global infeasibility.
P10 personnel search remains bounded by its existing 256-window/50000-state protections.

Independent fixed-output checking
No planner, resource preview, staffing allocator or material allocator is called. The checker
rebuilds machine dependencies and calendar/off/downtime coverage, material demands from
frozen sources, inventory quality/expiry/readiness, conditional supply eligibility/reference
limits, exact lot capacity/cumulative consumption and allocation conservation. The approved
material-demand formula helper and rational primitives are shared, explicitly not independent
implementations of BOM formulas. Tests separately assert 480kg qualified -> 500kg total input
and 325kg lean; they do not obtain expected totals from the allocator. Split quantity is derived
from original order/yield and route maxima before material verification; a smaller result
quantity cannot reduce requirements silently. Existing resource checker independently rebuilds
member tool/space declarations, personnel post identity and physical pool/group capacity.
Exact resource demand/capacity comparisons no longer round via Number.
Confirmation requires the new joint check to pass as well as existing replay/checks.
Minimal runs remain explicitly unchecked and cannot be confirmed. Explicitly disabled or
future tools remain unchecked; FR022-joint-v1 does not pretend they were adopted.

Compatibility and rollback
Old frozen runs have no new contract; calculate/replay does not synthesize the new fields.
No schema migration or bulk historical write. Old confirmed plans, confirmations, original
inputs and execution facts are preserved byte-for-byte/structurally as applicable. Candidate
confirmation under new software still requires current inputs and current complete checking;
recompute old drafts where the current freeze hash changes, rather than rewriting history.
Rollback by retaining old software/store backups and stopping new writes; never strip fields
or overwrite confirmed records to manufacture compatibility. No deployment performed.
