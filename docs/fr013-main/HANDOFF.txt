Behavior and contracts
Actual PG01 has a multiple-file input and a six-table batch panel. It previews current runtime Chinese fields, row counts, physical line coordinates and individual values. Blocking issues show file, physical line, field and reason; semantic native buttons work with Tab/Enter. A locate action focuses the selected physical line in the original CSV textarea; edits invalidate the preview, and a new preview is required. Textarea edits preserve untouched CR/CRLF bytes despite browser LF normalization. Quoted commas, escaped quotes and multiline fields retain their contents. Blank quantities remain pending, never defaulted to zero.

Atomic server workflow
POST /imports/preview accepts {files:[{name,text}],revision,reason}; edit membership and CSRF/reason gates apply. It checks file/header/shape/required fields, then calls the same saveInputs transition/history/business validation path in dry-run mode. No business file, revision, plan, inputVersion or audit write occurs. Invalid shape previews return valid:false with issues; existing validation/protection failures retain HTTP400/409.
A successful preview stores raw original files, trusted owner, revision, complete persisted-state hash and creation time in process memory for 15 minutes (capacity100). POST /imports/commit accepts {previewId,reason}. Caller-supplied tables/revision/actor are ignored. The server checks current membership/ownership/TTL/full state, reparses owned originals, reruns the existing saveInputs gates, then performs the existing one-file atomic-rename transaction. Confirmed/released/archive original inputs, immutable confirmations and current execution facts stay protected. Each changed table records trusted actor/role/reason/requestId and one batchId with old/new input versions. Repeating identical corrected files writes nothing and adds no audit rows. A consumed token, ownership mismatch or state change requires re-preview (409). Tokens are intentionally lost on process restart. No client-side validation can authorize a write.
Six tables are replacements, not append operations; cross-file dependencies are validated against the complete proposed state regardless file selection order. Any blocking error means none of the six changes are persisted. No empty-table import, unsupported all-category importer or coercion of legacy fields was added.
