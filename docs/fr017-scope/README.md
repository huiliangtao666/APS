## 实现

`configurationPreview` 只派生已有表16/18/19/12/15/23/29的范围、字段、来源及校验状态，不保存第二套参数。工装声明仍由 `effectiveClaim` 解析，替代资格仍由 `skillMatch` 判定；同一模块供 React 草稿预览及有成员权限的 `GET /api/rules/preview` 使用。后者含服务端评估时刻和原 revision，不修改状态，也不改变 `/state` 契约。

- 所有现有字段显示有效值与源表/行/字段。工装继承的数量/提前/后延显示工装编号及来源字段，逐项来源互斥，窗口不得叠加工序整段。
- 人员显示明确候选、所需技能、参与/释放窗口、共享容量、班次、实际可用期及每候选的同技能/有向替代资格。精确工序（含禁止）覆盖 `*`，显示被覆盖范围；无反向/传递。
- 规则区分未启用、待生效、未支持、缺项，以及采用。非法配置不显示采用；草稿缺项定位原行/字段。人员依赖为内在保护，LABOR关闭仍采用；最小模式不声称检查人员。
- 独立岗位、跨组同物理池、多班交接的前台选项禁止启用并说明模型原因。直接提交这些未建模字段由原有 schema 守卫原子拒绝。禁止不代表批准永久缩小 FR007/FR022 核心能力。
- 保存、权限、审计、原子 rename、revision、新运行冻结与原检查器均复用既有链路。本次没有改变执行器、规则值、枚举或默认业务值。缺项既不能自动补为0，也不在当前预览回填旧方案。
