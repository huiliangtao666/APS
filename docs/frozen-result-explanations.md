# 排程明细中的处理规则说明

依据：2026-11-03 用户要求将 DE620 未排分析涉及的处理规则写入明细，便于理解。此改动补充解释、判定证据和无任务需求的关联查询，不修改排程选择、约束或回滚算法。

## 查看位置

- 排程结果汇总：搜索需求编号，展开计算记录与来源。
- 六视图 → 需求交付 → 点击需求编号：默认明细直接显示相关说明；“处理规则说明”可分页查看全部记录。
- 六视图 → 物料风险 → 明细：同样可查看该需求的说明。
- 设备甘特节点 → 计算分析：相关已保存问题复用同一套规则解释。

每条说明包含处理规则、本次判定依据、结果处理、完善位置和证据说明。缺料、供给在实际投料时不适用、等待超限、资源或窗口无法安排、到货保质期不足、在制续作失败均有业务说明。过程记录与需求最终状态分开显示。

## DE620 类型：实际投料时供给不适用

1. 先按需料时点选取符合条件的供给，安排工序资源。
2. 资源候选确定后，复查原分配是否满足 `供给可用时点 ≤ 实际投料时点 < 到期时点`。到期边界不含。
3. 当前算法在本处失败后不自动替换供给批次，也不自动回退重排到有效期内。
4. 需求失败时撤销该需求本次新增任务、分配及资源占用，恢复供给余额。库存存在、没有缺料记录不代表投料时资格仍成立。

新计算在撤销前记录供给身份、物料、分配量、原分配投料时点、候选工序开始、实际校验投料时点、供给可用和到期边界，以及供给来源。

按日模型按候选开始所在日期复查资格；原分配和候选开始仍分别保留，避免把日期坐标换算误解为现场分钟作业事实。分钟模型保留原点下的分钟偏移。

## 其他判定证据

- 等待超限：记录前序完成、后序候选开始、实际参与比较的等待值、上限及比较口径。旧非参数日模型的整数日期差与实际时点差不混用。
- 到货保质期不足：记录制造就绪、最早发运、运输天数、要求剩余保质天数、物料保质天数及参与比较的两侧边界。
- 有限资源：记录设备组、班组、工装类型、待排量、最早候选和窗口结束边界；未保存逐候选排除轨迹时，不认定唯一瓶颈。
- 缺料：采用冻结缺口、单位和需料日期，解释条件供给与采购参考建议的区别，不制造逐批排除记录。

## 历史与来源

旧运行只保存了笼统问题时，展示对应业务规则及明确的证据缺口，不用当前参数、重新计算的候选或演示值补成历史事实。DE620 的已有记录属于此类；新运行才保存新增的数值证据。

无任务的未排需求使用真实需求编号关联问题和缺料，不依赖任务编号。说明及来源均受原查询、运行和冻结指纹约束。只读明细不写运行结果、输入或参数。
