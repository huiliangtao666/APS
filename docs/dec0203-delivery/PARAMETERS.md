## 唯一来源与前台维护

复用主 React「数据与 CSV」及跨表草稿保存入口，不需要写源码或原始 JSON。计划员/主管可维护，查询角色只读；所有保存要求原因。

| 对象 | 使用来源与范围 | 计算语义 |
| --- | --- | --- |
| 工装表18 | 编码/适用工序、可用数量、每任务需求、提前/后延、可用起止 | 可用数量为同一编号的共享容量，不会因多任务变成无限；实际占用须落入该资源可用期 |
| 声明表23 | 订单+工序+类型+资源唯一；启用 MOLD/STORAGE 后执行 | 参数来源「逐项声明」使用本行数量/提前/后延；「工装配置」继承表18这三个值且本行必须留空，消除冲突来源 |
| 工装/空间窗口 | 占用口径为原「显式逐生产批完整区间」或「明确窗口」 | 完整工序偏移只能为0；明确窗口为 [工序开始+开始偏移−提前取得, 工序结束−结束偏移+后延归还)；一条声明只采用一种口径 |
| 人员依赖表12 | 订单+工序+人员组+人员参与阶段；同阶段标识不得重复 | 可配置多行窗口；人数正整数；所需技能、班次及指定人员组必须匹配；偏移定义明确分钟而非从阶段名推算 |
| 人员窗口外释放 | 「是」或「否」 | 是：仅参与 [工序开始+人员开始偏移, 工序结束−人员结束偏移)；否：全工序保留该人数 |
| 重叠人员窗口 | 同订单/生产批、人员组、所需技能、班次的命名窗口 | 同角色重叠按最大人数、非重叠分别释放；不同技能或不同生产批按独立需求累加，同池总数统一扣减 |
| 有向技能替代表29 | 可提供技能→所需技能，是否启用，适用工序 | 精确工序优先于 *，包括禁止行；同方向同范围唯一；同技能直接匹配；只有显式启用的单跳边允许替代；无反向或传递推断 |

每套工装和人员组均按物理编号统一扣容量。人员依赖继续指定组，不自动跨组重新选人；同池不同技能不会额外生成容量。有向候选只检查该组实际提供的技能；多候选按配置技能顺序确定，并保留提供/所需技能、关系编号与原因。

## 单位、校验和版本

0分钟=2026-11-02 08:00 +08:00。使用半开区间，释放端点不占容量；相邻归还/取得可以复用。工装数量为安全正整数套，提前/后延和工装窗口偏移为0–525600整数分钟；人员人数安全正整数，人员非负偏移总和须小于明确工时。窗口端点在实际 Worker 中还会再次核对；不足时顺延或明确未排，失败候选不提交部分资源。

服务端 `/inputs`、单表、CSV、独立试算共用完整状态校验及原子 rename 保存。未知字段、失效引用、重复关系、非法窗口、负/非有限数、来源冲突及越权保存失败，不写入业务/审计。保存有 revision、操作者、角色、时间、原因、fromVersion/toVersion；新运行冻结配置并记录 `resourcePolicyContract` 与 `resourcePolicyVersion`。实际 Worker 使用冻结执行输入；服务端 verify、确认审查、位置复核接入独立固定结果资源检查器，重建需求窗口并核对资源账、技能方向、人数覆盖、实际可用期和峰值容量，不调用调度器的分配/找位函数。

方案中的资源账显示实际占用/释放分钟、采用来源及替代原因。新契约的独立复核在前台展示「工装 / 人员参数」；最小模式继续明确不检查资源，旧快照不会被追认成新契约检查通过。

## 迁移

MOLD/STORAGE 的新规则参数明确声明“按表23逐项配置/由声明参数来源选择”，不再把整工序写成唯一规则常量。原 FR022-v1 固定参数作为兼容协议接受；新运行的有效规则快照规范为 CR-DEC02-03-v1，原输入原文仍冻结保留。

仅当前输入读取/旧字段导入/新运行冻结时补充新增字段：旧声明参数来源=逐项声明、窗口偏移=0；旧人员窗口外释放=是（原偏移外本来释放）；旧工装可用期=[0,525600)；技能关系=[]（不允许替代）。这些可改的仿真初始值/待确认值在前台明确展示，并非用户批准现场参数。既有数量、提前/后延及参与偏移不变。新表单显式空关键字段拒绝，旧 API 缺失的新增字段走上述兼容迁移；旧 CSV 可省略新增兼容列，新模板包含完整列。

不会批量改写 inputVersions、旧 plans/runs/confirmations 或原资源账。修改当前参数只生成新输入版本及新运行。旧草稿如无法按新契约重放/复核，须另开新运行；不能静默替换旧结果。FR036 当前矩阵/表头及其散列同步新增字段；既有业务样例和历史输出样例字节未改。方案比较将参数指纹作为输入版本证据展示，不误判为计算范围不同。

## 有限交付的明确限制

- 同一订单/工序/资源仅一条连续工装/空间窗口；多条或整段叠加阶段会原子拒绝。本轮不引入事件触发释放、下游动态释放或不连续工装窗口模型。
- 已有执行事实且拟采用工装/空间约束或人员依赖的同任务，缺少原始资源占用事实，禁止保存/启用或新运行通过此组合。不把窗口偏移套到剩余工时起点，也不猜原始资源账。历史只读不变。若需支持，须在原 Issue 设计独立、不可改写的实际占用边界账后再实施。
- 单个人员组只有一个连续可用期、一个班次；无个人考勤、自动跨组人员优化。多角色同技能如需同时独立占用须使用不同明确人员池或另行设计岗位标识；同组同技能的命名阶段在本契约中表示同一角色的参与窗口，按最大人数合并。
- 阶段以相对实际工序开始/结束的明确分钟表达；无现场准备、拆卸、上下料时长猜测。原有连续机器日历约束、最大等待/其他未实现项不扩大。
- 浏览器证据来自隔离应用容器的真实 Chromium/React/Express/Worker，身份为 QA 合成成员和 runtime alias；未声称真实 Portal 网关/SSO、现场业务参数或 UAT 全量通过。待 APS-Test 从本交付 SHA 独立复测。
