Supported editing
All 16 current main-app tables: products, materials, supplies, supplyDelays, supplyUses, inventory, orders, bom, routes, times, machines, calendars, downtime, dependencies, personnelGroups and rules.
Planner and supervisor can stage additions, edits, copies and permitted deletions. Explicit save/cancel replaces per-cell blur writes. Copies retain editable values and must receive distinct unique keys before validation can succeed. Drafts survive category switches; all changed tables save atomically, enabling related route/time creation or coordinated deletion. Leaving the data page discards unsaved drafts, as the UI states. Current-data summaries are persisted values until save. Stale refresh disables save; the server independently rejects a stale revision with409. Errors retain drafts for correction. Restoring a selected plan's captured inputs is an explicit permissioned action creating a new current version; it does not change the saved plan or allocate/deduct stock.

Shared validation and write boundary
POST /api/inputs and existing POST /api/tables/:table call the same server save function. Import/edit/add/copy/delete/restore labels cannot bypass it. Full proposed state is checked before any mutation: schema/string types, known fields/tables, limits, composite uniqueness, quantities, supported units/enums, route/time/product/resource/calendar references, route cycles, P0 line scope, inventory amounts/expiry, BOM units/dates, expected supply/delay/use, personnel and rule JSON structure. Existing business validators are reused; configuration-only future resource semantics remain configuration-only. CSV parsing rejects malformed quoting, duplicate/unknown headers and inconsistent columns. Main-app imports replace the chosen table. Reimporting identical normalized values makes no state/audit/revision change and does not append quantities.
Errors include file, field and row (header-inclusive logical CSV row); row0 denotes aggregate/table-level findings. Strict parsing reports physical line for malformed quoting. Generic preexisting cross-record validators sometimes report an aggregate configuration field rather than a precise cell. This does not establish all future FR016 diagnostic acceptance.
Managed identity and current stored membership enforce permissions on every request; query users cannot mutate either path. Reason is required for writes, export grant still required for query export, and CSRF checks remain. Client identity/status/snapshot/audit claims cannot overwrite server identity or plans. Unsupported write URLs return404. Persisted changes include actor, role, server timestamp, reason, request ID, before/after rows, shared batch ID and from/to version IDs. Data, versions and audit commit by one atomic file rename.

Historical input protection
Before every accepted changed input, the previous complete input is retained. The new complete input is a separate SHA256-addressed version; every newly calculated server plan references the exact original version. Identity is the input-version/table/business-key tuple, rather than mutable rows inside an old plan. Versions are never overwritten or deleted through the application API. Snapshot values are cloned; version resolution verifies the hash.
GET /api/plans/:id/inputs and plan query views resolve original full inputs. The query page switches between current input and the selected plan's original input; relations use that selected source. Historical export is regenerated on the server from the referenced version, includes its hash and an original-snapshot label, and ignores body-supplied rows. New calculation uses current inputs; verification rejects stale inputs.
Old plans without captured inputs explicitly show historical inputs unavailable. Current values are never backfilled as historical truth. If persisted confirmed/released plans lack a valid original snapshot, input writes fail409 protected_history_unavailable. Test-only confirmed-storage fixtures prove immutable originals and corruption protection; no application flow fabricates confirmation.
