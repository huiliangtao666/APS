## 用户重申

1. 逻辑关联：用于顶层业务流内部对象之间、业务流与图谱底座实体之间，只连接到实体，不需要详细字段。
2. 计算关联：数据计算，例如数量。
3. 日期关联：排程日期及时点的依赖单独表达。
4. 行动关联：本体能够执行什么动作。
5. 约束：边界、规则、要求及适用条件。

## 修改

- 现行图例、下拉筛选及绘图只使用上述五类。换算纳入计算；身份、版本和来源读取作为定位/溯源依据；不再另列实体、版本、换算、推理等图例。
- 顶层业务流设置明确业务对象入口，46条逻辑联系只连接业务流对象或实体卡，17类底座实体均有入口。逻辑类型的应用定义也清除详细字段端点。
- 逻辑筛选独立按业务范围选择，避免因底层应用属于容量约束而漏掉设备/班组/工装、或因底层应用属于日期而漏掉交付对象。
- 原225条字段依据保持身份和端点，补充3条任务时间依赖。现有228条中，58条计算、28条日期、13条动作影响、67条字段约束；62条身份/读取依据不绘成逻辑字段连线。
- 计算与日期分别显示。明确“开始+已算定历时→结束”“前序结束→后序最早候选”“工装结束+后延→归还”“运输→到货”等日期依赖；容量/最大等待/效期/资格等判定归约束。
- 行动列实体、执行者、输入、影响和实现标记；57项行动的执行前提统一登记到约束。概念动作没有冒充已执行接口。
- 所有应用条件、失败/未知处理和变体适用要求，以及字段边界、行动前提集中到435项约束定义。强制/参考可作为约束属性，不扩成新的关系类型。
- 保持六列完整实体名、实际源字段及565来源绑定。原OWL原文不改写，在参考页明确标为原文对照，不代表现行分类或真实实例。
