# 每日联动用户测试接入说明

本阶段合同：[Issue 170，2026-11-09](https://github.com/huiliangtao666/APS/issues/170#issuecomment-6730265437)。原 r4 内部固定源码交付结论不变，用户交付阶段单列。

## 源码与界面

本实现从 r4 的 551 文件固定源码内容树 `015c9c50244cc484b6302ba5cbcc1194d1306b3449844bb2b496489e05a22615` 精确吸收每日模块与现有单页 UI 的依赖。原观察源码没有作者 Git SHA。保留 main 的需求文档及其他文件，不导入 `server/data*`、原 Excel、运行状态或观察清单，不删除旧源码。候选 Git SHA、逐文件来源和源→main 映射见同原 delivery 的 r5 正式结果，避免在提交内自引用。

工作台沿用现有单页排程/插单、查询、比较和报表。每日总览展示分支、日期、四输入确认、基础计划及实际日报；四类输入可以预览并接纳。生成计划本身不扣料、不生产、不发货。真实反馈须分别填写累计耗料、累计产出和累计发货。采购草稿须明确供应商、供货关系、MOQ、倍数、收货库位、效期和质量；生效、实际收货是独立操作，待检收货不增加可用库存。

历史日报从成功日结快照计算，只读显示；返回当前日后才允许写入。修改表单会清除旧预览，明确 HTTP 拒绝会刷新修订；未知提交结果保留原请求编号供查询，不盲重放。原独立分支 API 保留；此固定数据集页面不提供跨数据集 fork 切换按钮。

## 部署准入

此文档和源码不代表已经取得用户入口。APS-Dev 当前旧生产绑定仍为 `aps-r1`，预览脚本只选择工作区活动绑定，不能将该旧入口当作新版本。独立工作区创建请求实际返回 `401 — User principal required`。本轮未改旧绑定、未启动旧 dev/prod、未公开发布。

由具备工作区创建权限的用户主体或平台管理员配置独立轻应用工作区后，才能继续使用该工作区自身的官方 `workspace-app-builder` / `lite-app-scaffold`，在新目录和新数据上绑定并启动受限预览。需重新核对实际 SDK、分配的 servicePort/base、HTML/首屏 JS/CSS 与真实业务请求；浏览器使用官方脚本输出地址。不得借他人凭据或以修改鉴权解决创建权限。

## 样例及恢复

r5 SAMPLE 同时包含独立的 `seed/` 与实际执行后的 `checked/`。seed 由仓库 `qa/daily-fixture.mjs` 的显式 mock 生成，不是 r4 已执行状态的期初替身。两者必须恢复至新私有 state/uploads；不覆盖原配置、state、native、frozen、B/P 或三个保护卷。具体 bytes/hash、样例路径与恢复步骤见 r5 RESTORE 与 SHA256。

已验证的短链：初始原料 85/70/1 千克、包材 1500 米；基础计划保存/采用不生成实际量；实际生产发货 FG101 20 千克后，原料和包材为 68/66/1 千克、1300 米；RM101 采购 100、收货待检 30 后实物 98、可用 68、未收 70；日结历史保留当日值，次日自动收货与旧日历史分开。重开后同请求回执可查询、重复日结回执不重复扣料。

## 边界

当前正式结论须按 r5 结果读取。标准构建和开发者 HTTP/Worker 自测不等于浏览器主路径或用户可访问验证。真实 CP 不可用时保持明确不可用，不静默回退。完整 40 场景、全 12 MPS、完整现场数据、未知 fsync/强杀/并发、独立 QA 及用户业务 UAT 未迁签通过；此次不启动 #157 或新现场默认值。
