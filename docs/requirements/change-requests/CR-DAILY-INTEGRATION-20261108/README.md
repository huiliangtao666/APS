一、变更目的与当前授权
基于目前用户已确认的排程/插单单页及现有主程序，将需求、库存、生产、排程、补货和报表整合为按业务日工作的完整流程：准备本日数据→四类输入确认→排程/插单/比较→保存并采用→登记实际收发和执行→日结→将未完成及未收部分带入下一日。用户原话：“再刷新一下最新逻辑与UI实现情况，更新差异部分作为一个CR提交给PM进行开发调度”。本包据此提交一个完整差异CR，供PM登记、组织批准流转并按现有授权调度，不再重复询问相同设计方向。
需求依据为 APS-BL-002 / V2 及适用后续增量；V2.1综合说明记录近期UI/UX，R2是本次布局依据，R3是完整版业务设计。范围基线不改写、历史原卡和证据保留。新CR的提出不等于全部新默认值、真实外部连接或发布获批；这些仍依实际授权处理。Design不承担项目派工和实施状态回写。

三、本CR应交付的差异
1. 六模块共用业务日上下文。在现有抬头/组件上组合需求、库存、生产、排程、补货、报表；保留插单独立入口、现有单页流程、比较及查询/结果入口。共用场景、分支、业务日期、计划粒度和当前/历史状态；同一业务对象只维护一处，通过模块入口就近使用，不复制第二套主数据或配置。
2. 四类日输入及确认。需求、库存、生产、补货均支持Excel、外部接口适配、在线仿真三种来源的预览、校验、接纳、查询维护和确认；接入原导入/维护接口，不另造文件格式。无新增数据的领域也可确认“本日无变化”，仍绑定当前余额/主数据/参数版本。首轮接口可用明确标识的local mock验证合同，真实连接在来源就绪后单独接入，不冒充已连通。
3. 采用后的真实反馈。沿用执行事实、四态、累计比例和净剩余规则，把实际领料、合格产出、发货、损耗/报废、质量放行、盘点等有来源事实纳入日流水。生成、保存、采用计划以及试算本身不改变实际库存、需求已交或任务已完成。
4. 补货业务闭环。缺料建议、采购草稿、生效订单、在途、部分/全部收货各有状态；未生效草稿仅作条件试算，不进入实际在途。生效订单按交货日默认仿真收货，应用已知延期/取消/质量事件后再判定，批次与库位、可用状态有依据；采购未收余量跨日保留，不随重排重复订购或重复入库。
5. 原子日结与次日接续。四类输入、当前采用/执行状态、账物对账通过后才日结。冻结D日输入/参数/计划/执行及余额，并以同一成功提交建立D+1状态；新日先应用当时已知且已生效事件，再进行到期收货，随后四类输入等待确认。保留原需求交期、稳定任务身份、未交/在制/采购未收量。失败或未知回执不能产生半个业务日。
6. 报表与回溯。在现有MPS和五类查询上增加实际收发、有效在途、采用计划、条件建议、跨日余额及来源；按物料同单位核平。旧日及旧run读取其冻结版本，不能混用今天的主数据或事实。12类指标使用R3字典与现有MPS对应，不重复实现已有九指标/浮窗。

四、页面和交互的具体调整
所有新入口沿用最新main对应产品分支的白底、紧凑表格、抬头、字体、按钮与抽屉组件；复用V2.1 UI规范，不另做一套视觉风格。抬头下显示场景/分支、业务日期、日/分钟、当前/历史、“每日总览”和“日结并推进下一日”；日历切换已有日期只切查询上下文，不得凭一次改日期创建业务事件。
需求页：本日需求台账、导入/接入/仿真预览、维护确认及客户/产品关联参数。库存页：批次/库位/质量/效期与收发、盘点；生产页：设备/工装/班组/工艺、日历、可用事件和实际反馈；补货页：供货主数据与相关配置、建议/订单/收货。同一对象在各入口编辑同步有效值并留下修订来源。
排程页保持用户已确认单页布局：本日输入检查与四确认、策略配置、计算、结果保存/采用均在原区域；插单保持五步默认展开且可独立折叠，重开保留输入，原已完成九指标按稳定原工序身份复用。比较不修改共享事实。紧凑总览展示各域确认/待处理和最后成功日结，可点击定位缺项，不用大卡片挤占表格。
查询筛选内搜索多选，初始/重置全选；清空为0结果，不暗中当全选。逐表栏位选择，来源/明细抽屉分层，默认100/200/500分页；物料/BOM已确认的专用“默认全部、25/50/100”例外保留。物料筛选支持“根据BOM显示”，按有效日递归且共享子件去重，不增需求、不重扣库存。不增加讨论意见入口。
日期全部显示日历日期。需求、库存、补货按天；生产排程按分钟计算保存、半小时刻度展示，17分钟不能四舍五入成30分钟。日/分钟能力沿原卡接入，历史版本保留原粒度；本CR不把日量模型冒充分钟求解。

五、数据合同、确认失效和状态边界
每日上下文至少包含场景/分支、业务日、父日结/父采用计划、粒度、当前修订、四领域接纳及确认版本；输入来源至少包含渠道、源系统/文件及sheet行、业务身份、源修订、源事件、发生/可知/生效时间与单位。运行继续使用现有冻结输入hash、readiness token、run和计划ID，补上下文关联即可。阶段性副本及试算不能成为实际库存权威源。
同业务身份跨渠道重送遵守幂等：同内容不新增，异内容明确冲突或预览为受控修订；来源不是用三个渠道各造一笔业务。参数定义、边界或有效值冲突，以第二份P为准；B中可用值、在线合法修订与对象/有效期覆盖继续按现有规则追溯。P重导不能将非法旧值以“保留手改”方式放行。
四确认绑定确切修订；需求变化影响需求确认/排程就绪，库存/收货/领料影响库存及相关生产/补货就绪，资源/工艺变化影响生产及相关候选，采购生效/延期影响补货及相关供应。系统按引用关系失效；不要求用户重新输入未变领域。任何影响候选的依赖变化使原候选仅可查不可采用；已保存/已采用旧版本保留，不被改写。
状态链：输入为待接纳→接纳待确认→确认；计划为候选→保存→采用，失败/取消不替换原采用；采购为建议→草稿→生效→部分收货/全部收货（取消针对未收余量）；实际执行/发货为独立有来源事实，不从计划完成比例猜实绩。四态和已开工净剩余规则采用原实现。
累积数量反馈仅记差额：本次有效累计−已记有效累计；相同累计重放差额0。回退更正必须关联原事实并有更正依据，不可静默当新累计或重复扣全量。取消需求不能重复扣除已在有效总量中减掉的取消量；有效总量不得小于有效累计已交。
有效未收采购量=有效订单量−有效累计收货量−已取消未收量；需要统一总量/修订口径，不能把改小后的订单总量再减同一取消量。草稿条件供应单列；到期可默认收的仅为已生效且未收余量。真实与仿真回执对应同一实物时以同一身份入账，无法确认对应关系则待核，不把两份都加库存。
实物期末=固定期初+有来源实际入−有来源实际出；逐物料按其基础单位核平，不把千克和米相加。可用量单列质量、效期、预留/分配；待检到货增实物、不增可用，放行增可用而不二次入实物，过期不可用但仍属实物，实际报废另记出账。生产产出不等于发货，BOM投料基准已含损耗时不能再除同一收率。

六、开日、日结、恢复和期末
本场景使用2026.10.31真实期初，首业务日2026.11.01，结束2026.11.30，滚动14天且月末截断；这些是场景输入，不改现场默认。业务日不等于机器日期。日内截止、时区、质量放行规则不能擅自补成00:00或合格；日模型可用明确日界，分钟承诺缺关键边界时应说明缺项。
日结顺序为：检查四确认/未保存候选/实际流水及余额→冻结D日快照→在隔离新日副本中接续未完成→按D+1当时可知且已生效的事件修订对象→按新交期/状态收有效订单剩余→新日四领域待确认→原子提交。事件记录的发生、可知、生效各有含义；未来才可知的脚本不可提前影响当前排程。已知延期必须先于到期默认收货判断。旧日快照不能包含次日到货。
未执行日允许带原因日结；计划未登记实际不自动生产、不耗料、不发货。新日接续原需求和任务身份及净剩余，不把计划任务按新runID重复创建。已发生、已完成、已锁定保持原保护；未完成实际事实继续累计。当前日已确认的无变化输入与期末余额仍留来源。
同一场景分支同一业务日仅一个有效推进提交；重复请求/客户端超时/服务重启通过同一请求身份查询已提交结果，不盲重放收货与扣料。未知落盘或下游回执停在待核状态；确认实际提交后继续，失败则保留上个成功检查点和原日。原模拟器A持久化/幂等可复用，新增跨主程序接缝必须验证，浏览器缓存成功不是正式事务证明。
历史已结日只读，调整通过新分支；分支库存/采购/实绩不回灌原分支。2026.11.30结束本期仅冻结末日，未交/在途仍可查，不自动开2026.12.01。连续N日沿现有能力显式使用；首轮人工逐日可完成闭环，不把自动采用/自动实绩或定时任务列默认。
