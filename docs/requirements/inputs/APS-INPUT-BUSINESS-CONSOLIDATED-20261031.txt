0.2 物料损耗与标准投入定额（B09，CR-BOM-LOSS-20261031）
用户原意：损坏比例拆为原料损耗、生产损耗、运输损耗；允许按物料配置，未覆盖继承统一参数；统一参数三项初始值均0%。各物料生产损耗可不同。
标准定额是该配方基准下的投入量，不受原料损耗、运输损耗改写；合格产出受生产损耗影响。
适用于同一投入基准、同一kg量纲的配方：
  q_i = 物料i的标准投入定额；p_i = 解析覆盖/继承后的该物料生产损耗比例。
  Q = Σq_i；O = Σ[q_i×(1−p_i)]。
  派生总生产收率 = O/Q；不是逐物料收率的简单平均。
  目标合格产出T所需物料i标准投入 = q_i×T/O。
不再额外乘或除旧固定产品总收率，避免重复扣生产损耗。原料/运输损耗单独展示与冻结，不擅自叠入上述公式。
统一值和物料覆盖都可维护；显式0应覆盖统一非0值，清除覆盖才恢复继承。比例有效范围0%～100%；基准Q必须正；O=0不可反推正目标。不同物理量纲必须有明确转换，包材个数不能直接加入kg配方求总收率。
独立算例（仅说明，不是默认配方）：每1000kg投入LEAN650/FAT150/WATER150/PREMIX50，生产损耗分别2%/4%/10%/0%，产出637＋144＋135＋50=966kg，收率96.6%。若目标1000kg，LEAN投入为650×1000/966kg，其他物料同式；精度与展示取整不得反写精确值。

0.3 原Excel与标准投入模型的来源区分（B09/B12/输入数据）
当前原Excel物料清单按“每1000kg合格产出、定额已含本层收率”解释；保留原件、数值和来源。目标合格产出T时，子件需求=该基准用量×T/1000；不得再次除该层收率或追加生产损耗。
用户新维护的“标准投入＋逐物料生产损耗”记录按0.2计算。两类记录至少显式携带：基准类型、基准量和单位、是否已含收率、版本/有效期、来源profile及来源定位。
不得将Excel原定额硬填为标准投入后再扣损耗；不得由一个旧总收率倒推每物料损耗。切换来源需明确转换依据和完整输入，保留历史版本，不能静默改写。
仓储损耗参考率不等于原料/生产/运输三项损耗。原09六列CSV、Excel原文件、旧冻结方案和旧SHA PASS保留原语义。
本次合并更新输入需求说明，不修改原Excel的29张表、参数值、公式、引用或历史文件hash；新增配置通过版本化输入合同承接。输入映射附件若需扩展由实际实现同步维护，不声称原307字段已经包含新增损耗字段。

0.4 包装工时、速率、包材及尾批（B12/B15，CR-PACK-BATCH-20261031）
用户原文：“包装按照工时*速率计算，工时和速率是可配置项。包材按照最小包装单位取整。不足一批可以生产，可以合并。”
包装产量=工时×速率，两项可配置，单位及时间基准显式匹配。给定目标数量和正速率时，包装所需工时=目标数量/速率。不固定50分钟，不另外要求一个未指定效率系数，不擅自叠乘效率。
包材按配置的最小包装单位向上取整以覆盖实际需求。技术拆批不能重复造成包材需求放大；实际合并作业应保留数量和来源，不能凭空共享不同作业的剩余包材。
不足一满批允许生产，按实际投入与产出，不超产补满。兼容批允许合并，但仍检查程序、容量、物料、资源、日历及最大等待，保留原订单/成员/投入产出来源。
固定热程序不因尾批少量自动缩短。新物理单位转换、任意混批/装载等未采用扩展，不因本条自动获批。
真实工时/速率/最小单位可由用户后续维护，开发测试与QA先用显式、可替换、可复演的mock，不等待真实现场数值。

二、页面与维护方式
主导航增加“输入数据”，与“排程工作台”“方案与运行”并列；升级原“数据与CSV”能力，保留旧CSV入口和已有历史资料，不出现两个独立维护的数据真源。
顶部显示：数据集名称、仿真标识、版本、快照日、日序基准、排程起始日及窗口、数据就绪状态。主要动作：导入Excel、查看导入记录、选择数据集、检查数据、用于本次排程。只有保存数据不会静默替换工作台当前版本；采用前展示影响，采用后使旧检查过期并要求重检。
四个子页固定为需求、库存、生产、补单。配置为四子页共用的“配置参数”入口及侧栏，不增第五类；业务表中相关单元格提供“维护对应参数”，保存的是同一参数记录。每张表顶部一行综述，紧凑行距，编号及名称同时展示，无“主数据/配置参数/业务数据”的大抬头。
需求：每日需求、客户与交付、每日成品汇总；按客户/区域/等级/产品/日序筛选。每日需求是按日明确需求，不导入促销、波动预测或销售订单流程。需求编号保留；内部若映射到排程订单，保留该编号及来源类型，不能因现有程序只选“正式订单”而漏掉每日需求，也不能虚构已签销售订单。
库存：物料主数据、单位换算、库区库位、期初库存。按SKU/来源/环境/库位/批次/质量/到期日筛选。既有采购在途及在制可在库存页关联查看，分别由补单、生产维护，不复制成第二笔供给。物料来源展示采购/制造/包装；包装外购也走采购补单。
生产：BOM与版本、路线工序、设备工装、班组、工厂日历、停机、期初在制、生产补给建议及BOM/提前期/资源关联图。BOM按父项展开，产品可定位工序、设备组和物料投料点；设备反查使用工序。图由本版本结构生成；原Excel图形只作附件参考。
补单：供应商与供货条件、既有采购在途、每日缺料净算、物料需求来源、采购草案、采购缺料汇总。这里的订单是生产缺料对应采购订单/模拟补单，不是销售订单。按供应商/物料/需料日/到货日/草案状态/提前期风险筛选；从缺料定位每日需求、BOM关系、库存批次和供货关系。

三、一次性工作簿导入
支持当前29个sheet的整文件导入；第1行为综述，第2行为中文字段，第3行开始数据。识别的是明确版本的中文业务表及字段，不按sheet顺序猜类别。02/03/04三个CSV为本版映射附件，覆盖工作表、字段及集中参数引用。
本例16张输入表、7张参考结果表、3张说明表、3张图示表；后两类不生成业务记录。不能把图形、说明、Excel命名区域或超链接当作输入表。业务列允许调整顺序，按字段名识别；重复表头、缺必填表/列、冲突映射为错误。额外非空未知业务表/列列入预览，要求明确忽略或补映射，不能静默丢弃。空行跳过但保留物理行号；业务编号按文本保持，名称中文原样保存。
本版完整输入profile要求16张输入表及其表头；无业务发生的表可为空，引用与启用规则决定能否采用。7张参考结果表、3张说明表及3张图示表可缺省，不影响源输入资料保存；当前原件29张均须正确分类。模板版本变化须显式兼容映射，不以文件名替代模板识别。
步骤：选择文件和新数据集 → 自动识别并校验 → 预览四类、表行数、增改影响、错误/提醒/参考结果分类 → 确认一次提交 → 全部成功或全部不生效 → 展示新版本及采用入口。用户无需拆成29次上传。解析、校验和提交显示真实状态；中断后可查该导入批次状态，不能误报成功后再重复提交。
缺字段、外键不存在、重复主键、参数冲突、BOM循环/有效期重叠、非法单位/数量/日序等影响解释的错误阻止整批提交。已可解释但尚不支持排程的资料可以完整保存，必须显示“导入成功，尚不能排程”及具体能力/字段缺口；这不等于“数据就绪”。资料保存和用于计算采用两个可见状态。
初次导入新建隔离数据集，保留现有测试资料和历史输入。以后重复同文件、同目标数据集的提交返回原批次/版本，不叠加库存、需求、WIP或在途。改版文件先预览差异，再原子形成新版本；默认不把整表缺行理解为删除，也不把本文件当全局最新快照覆盖其他数据集。新增版本不得重新应用历史完成量或重复扣料。
确认提交绑定文件hash、模板版本、映射版本、参数版本、目标数据集和预览时的目标版本；期间变更则重新预览，不提交过期结果。保留原文件、原sheet/物理行/单元格/编号到业务记录及运行记录的来源关系，跨刷新重开可追溯。
Excel公式不交给任意执行环境运行。配置参数表的参数值为权威来源，业务展示公式通过白名单映射重建；现有公式缓存仅作一致性核对。已知派生列的陈旧缓存给出差异提示并重算；输入列出现未知公式、外部引用或不能解释的公式则报错，禁止按旧缓存悄悄导入。原文件和公式字面保留用于解释。
参数唯一性按对象、参数语义、有效期校验；相同参数允许多个有效期版本，区间不得冲突。对象编号映射到具体物料/客户/关系/资源/日历，不只凭参数名称猜归属。业务表维护参数时调用同一配置入口，不能把公式列改成第二权威数值。全局与对象覆盖沿已批准语义，未知继承规则不得猜测。

四、输入、派生和草稿的数量边界
2150行每日需求是唯一需求明细；430行每日成品汇总从中生成，不再次累加。箱数×每箱净重得到千克；需求日期、客户交付条件、运输天数改变后重算对应时间范围与保质要求，不能继续用Excel旧派生值。
420批期初库存为实物，55行既有采购在途为条件供应，8批在制为预计供应；三者按独立业务身份保存，不能把到货等于合格可用。期初在制历史投料已反映在期初净库存，不能再扣；未来尚未投料的部分需有显式来源，不能猜0。库存可用量不能小于0，也不能重复扣已有占用。
库位的储存环境/温度/卫生类别和物料要求需一致；质量状态、放行日、到期日和投料日共同决定可用。仓储容量的量纲明确，千克食品与个数包材不可直接相加；跨单位容量无合法换算时阻断相关检查。仓储损耗参考率仅作有来源参数，不自动等同原料/生产/运输三项损耗。
7张结果表保存为“导入参考试算”，应用结果由当前版本重算。原静态净算假设建议供给可在需料日到达；其期末量不是已确认可用库存，不能用它证明排程可执行。Excel原图、关键路径和试算也不是APS算法的唯一正确答案。
生产/采购建议可“复制为模拟草稿”，独立草稿编号及来源运行版本；允许维护数量、候选供应商、拟下单/到货日期和说明，并检查MOQ、订货倍数、供货关系和日期。建议行仍保留原净缺口，调整量与原建议并列；仅改采购量不能抹除剩余缺口或时序风险。
草稿状态：参考建议 → 模拟草稿 → 已纳入本次试算 / 作废。纳入是显式动作，生成可识别的一次性条件供给引用，不创建真实采购单；反复纳入或重试不重复供给，修改/作废仅影响未来版本。实际既有在途必须从其表维护，不能将草稿与在途同源数量叠加。参考供应商不等于锁定供应商，维护时可在有效1～3家供货关系内选择。
MOQ示例（独立测试数据）：净缺口101千克、MOQ200、订货倍数50，建议200；缺口211则建议250。计算式为倍数×向上取整(max(净缺口,MOQ)/倍数)，前提数值单位一致、倍数>0；供应商切换后重新取得其导期/MOQ并重算风险。
采购时序：预计可用日=拟下单日+采购导期+检验期；理论最晚下单日=需料日−采购导期−检验期。下单日不得早于当前可操作日，来不及时明确缺口/延期，不能反填历史订单或假设即刻到货。包装SKU同样遵守该规则。

五、天、数量与BOM的接入合同
本数据集按自然日整数展示和维护，不引入小时输入。日序0=2026-10-31，日序1=11月1日；11月共30天，31～43为12月尾窗，不存在11月31日。快照日0；首次排程从1开始，14天窗口为[1,15)，包含1～14。月度需求1～30与尾窗31～43在筛选及统计中分开。
区间字段一律开始含、结束不含；停机[5,6)只停第5天；保质到期日E不含当天；参数有效期[生效日,失效日)。需求日/最晚到货日表示该日内可交付，转换成时间边界时使用下一日开始作截止，不把日序d错误当成当天开始已超期。运输按整数自然日处理，先显示最晚发运日，再转换截止。负日序仅在历史事实/理论释放日允许；不能导入不存在的公历日期。
时区继承既定本厂+08:00，本数据profile显式记录Asia/Shanghai。现程序旧输入时间原点是2026-11-02 08:00+08:00，不得整体改写。若内部仍用分钟，日边界B(d)=1440×(d−2)−480；例如B(0)=−3360、B(1)=−1920。新profile需支持上述负内部坐标；不能被旧startMinute>=0校验误拒，亦不能静默平移日历/供给。也可采用显式日模式，但端到端必须保持同一基准，技术实现由Dev确定。
“跨日历时0天”表示同日加工段，仍有数量、产能、资源与顺序约束；不能转换成零占用任务从而无限并行。日班次数以标准班次为分母形成日产能比例，周日1/2，不能当全天停工或按2倍开放。日粒度不证明日内可执行；同日容量/资源及顺序需被实际支持和检查，缺少日桶或合法内部映射时明确阻断相应排程。
计划停机可从可知日采用；非计划事件在模拟当前日达到可知日后才影响新运行，第一天不能提前知道第15/26天故障。此工作簿实际5次停机是样例数据，不是以后每月必须限制5次的产品规则。供应延期率等参考参数不自动随机重抽；需要随机试验时固定情景版本/种子，未启用不宣称验证该风险。
制造本级提前期取配置生产提前期；采购及外购包装本级期=所选参考供货关系采购期+检验期，生产期0；累计期=本级期+max(有效子件累计期)，叶子累计=本级期。必须无环，检查有效BOM版本与优先供应商选择并解释并列关键路径。库存、排队和运输不藏入该累计期；关键路径是资料提前期，不是有限产能的承诺交期。供应商改变后重算受影响父项。
FG001样例累计12天，本级3天、最长子件9天；10种成品累计为12/11/13/13/13/12/13/11/12/12。本版主数据关键路径按所声明的参考BOM版本计算；实际运行按投料日有效版本重算。不能把父项名称或固定三层硬编码成业务上限。
箱、件、千克、吨及包材个数区分维度；通过本SKU换算，不用中文名字推断净重。同SKU转换一致，不允许将1000千克当1000箱；无关量纲不比较，数量展示取整不能反馈改写精确输入。供应订货倍数及包材整数约束分别检查。
重要来源区别：本工作簿BOM明确以“1000千克合格产出”为基准，子项用量已包含该层收率；目标合格产出Q时，该子件需求=基准用量×Q/1000，不能再除0.96。该来源口径必须标识为“合格产出基准，已含收率”，不能无损失地硬塞进旧“1000千克标准投入”字段。
最新CR-BOM-LOSS-20261031的“标准定额为投入、逐物料生产损耗派生产出”合同继续有效，不能被本文件覆盖，也不能反过来把旧样例重新扣一次损耗。输入接口须携带BOM基准类型、基准量/单位、是否已含收率、版本及来源；两个profile分别解释。若选择最新逐物料损耗模型，须有显式投入基准及各物料损耗，不能根据旧总收率猜每物料损耗。03/04映射保留原样例值；模型冲突列为可定位的就绪缺项而非“原始BOM已支持”。

六、主程序数据接口必须同步生效
这里约定业务交换内容与一致性，不指定接口路径、数据库、序列化类或算法。Dev在现有接口上升级并提供兼容说明，不能只加一个前端Excel查看器或浏览器临时缓存。
统一输入包至少携带：数据集/版本、schema及来源profile、文件及映射指纹、快照日与时间基准、选定产线、四类记录与唯一键、参数及有效期、输入/参考/草稿/预计供应性质、来源追溯、检查结果和不支持能力清单。每个对象保留物料/单位/批次/供货关系/BOM版本/路线工序/资源归属，不能降级成没有引用的中文展示文本。
界面维护、整本导入、旧CSV导入使用同一业务校验及采用模型。保存数据后服务端可查询重开；工作台选数据集及需求范围时使用指定版本。服务端按该版本冻结输入再提交主程序/Worker，计算过程中用户修改只形成下一版，不改变正在运行的输入。
接口不能只映射orders/routes/machines而遗漏其他已启用数据；BOM层级、采购及包装来源、换算、客户交期窗口、批次质量有效期、在途及WIP、日历停机和资源容量等被启用的业务信息必须在运行输入中有对应关系。每日需求转内部订单的记录数及数量守恒可核对，跨版本不能重复计入。
若某字段资料可保存而当前引擎尚不支持其计算，在数据检查、运行准入、结果检查范围和导出中统一报告。必要约束不支持则拒绝该范围的正式排程，不能忽略字段后输出“全部通过”；选择有限支持范围试算时明确标注受限及未检查。整工作簿功能的最终验收仍要求目标范围可运行，不能用长期“不支持”代替开发完成。
运行输出关联run、冻结输入/配置/映射版本、采用profile、需求与供给身份及检查范围；结果查询、甘特、缺料、补单建议、方案保存重开、原生导出、独立复核均从同一冻结对象读取，不能拿当前最新库存拼旧计划。旧CSV、旧分钟模式及历史方案继续按原profile解释，旧模板不自动升级到新的BOM或损耗语义。
数据导入状态、数据就绪状态、运行状态、检查结论、草稿状态分别显示。问题结构能表达中文原因、严重性、对象、字段、原sheet/行/单元格、相关需求及解除方式；无原Excel行时提供新建记录来源，不伪造单元格。

七、已识别的数据接缝与补充责任
G01：现文件没有产线归属表。可由新数据集创建时显式选定一条仿真产线，统一绑定本数据集的产品/路线/设备；保留选择来源，不猜真实工厂归属，不开启P1多线。模拟名称可由QA补充。
G02：20种制造半成品有BOM/生产提前期但无完整制造路线；87行路线仅覆盖10种成品。制造半成品不能伪装采购或自动认为无限产能。Design提供所需字段合同，QA可依仿真材料补充路线、资源适用及容量，标仿真版本；Dev确保完整多层投料/供给可解释。未补前可维护并看缺项，完整制造排程不就绪。若采用“外部半成品计划供给”只可独立受限试算且明示其能力范围，不能作为本目标完整通过。
G03：工装按类型引用，人员为班组汇总，部分投料位置是业务名称。需要显式类型→物理资源/池、工序名→路线工序ID、同日容量及WIP剩余资源占用映射；不把多个可用单位重复映射成多套物理容量。QA可补可复演mock映射，Dev校验唯一性；缺失不能暗设无限资源。
G04：本文件BOM合格产出口径与当前主程序投入基准不能直接同列赋值，处理方式见第五、六部分；不擅改最新CR标准投入及逐物料损耗。接口先分清来源基准，待补源数据不能拖住无关表查询维护。
G05：0天同日段、客户交付弹性/保质比例、库位量纲、在制预计供应等需在新运行profile中逐项声明采用与检查能力；未经支持不能因导入保存成功就宣称已排产。既有原包中同义能力复用原实现和证据，新增部分补验。
这些是设计/数据就绪接缝，尚未构成产品缺陷，不计修复轮次。QA可自主补仿真参数及场景，不要求用户先提供真实现场账；新业务公式或与已批准规则冲突的值仍交PM协调Design澄清，不能用测试值批准现场默认。
