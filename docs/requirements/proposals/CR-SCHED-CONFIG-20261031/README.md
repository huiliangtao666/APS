# CR-SCHED-CONFIG-20261031：排程参数可配置原则与遗漏项归集

本材料是Design提出并交PM登记的需求变更。用户本轮已明确“排程相关参数尽量可配置，不要写成固定逻辑”及“已有的继续，没有的等待开工”。本材料承接该授权；参数默认值、候选业务含义及未开工功能不因归集而获得额外批准。

- 提出人：APS-Design；登记、原任务关联与调度：APS-PM。
- 来源版本：APS-BL-001 v0.3＋各条需求适用的既有CR。原基线只读。
- 目标：原有效要求叠加本CR的配置原则和未覆盖增量；既有CR保持原身份，验收结果保留原范围与SHA。
- 交付事件：`design:scheduling-config-cr:20261031:r1`。新产品SHA=null；本轮未执行产品测试或UAT。
- 文件：`change-request.json`为变更请求；`tracking-groups.csv`为12个归属组；`parameter-inventory.csv`为69条语义索引；`affected-requirements.csv`为47条FR/BR原卡影响映射；`acceptance-matrix.csv`为专项验收；`sources.json`为固定来源。
- 12组是对应业务包的追踪目录，69条是包含复合字段与重叠来源的语义索引，不是12/69个新任务。现有40参数原名、候选/仿真值完整保留。

## 变更前后

变更前：基线已有数据、日历、工装、人员、规则、BOM等分散配置要求；后续CR、P10/N06和UAT讨论不断补出参数。相同主题缺少统一的来源与任务归属索引，示例值、临时假设和产品固定逻辑容易混淆，遗漏项不一定进入原任务。

变更后：排程业务结果依赖且可能随产品、工序、资源、订单、时段、产线或策略变化的值与选择，优先用显式配置表达。每项能追溯其语义、来源、批准边界、目标业务包、原FR/BR/AC/UAT、既有CR及开工条件。已有任务沿原授权推进；尚未开始的增量进入原任务的待开工事项。

这不是对原61项的批量重开，也不是把所有算法内部常量、验收标准和业务不变量做成用户开关。

## 共同配置要求

1. 配置字段必须说明中文业务含义、类型、单位/精度、合法范围、引用对象、适用对象、缺值/未知处理、互斥/依赖关系。枚举、公式或边界未明确的项先作需求设计待办，不能用单一mock偷偷补成已批准规则。
2. 可由业务维护的参数提供有权限的维护入口、说明、校验、保存状态与版本，不能要求用户改源码或原始JSON。测试profile由QA构造和维护；工程运行预算由Dev说明配置位置、单位与支持范围，无须把算法术语放进普通业务页面。
3. 适用范围、覆盖优先级、生效/失效、冲突处理须明确。已有契约沿用；不存在统一授权的继承层次时不凭本提案发明固定顺序。
4. 新运行冻结本次数据、配置版本及来源；排程器和独立检查采用同一批准语义，并能从冻结源独立重建检查。配置改动不改变正在执行的运行或历史输入、已保存/确认方案、执行与耗料事实。
5. 缺关键值、非法单位/引用、互斥组合或尚不支持的组合明确提示，不能默认0、无限容量、质量合格或自动关闭必要规则来得到结果。不支持项作为明确待办，不把永久禁用当完成核心能力。
6. 参数变化须能在新试算的占用、数量、可用时间、工时、排序或原因中体现；不能只有表单保存、实际计算仍写死。检查结果、页面和导出可追溯所采用值。
7. 容量/数量守恒、必需顺序、资源可用性、单位维度一致、历史保护等不变量不能由配置绕过。业务可选择的具体政策与这些约束分别描述。
8. mock默认明确标注SIMULATED并可替换，记录构造规则、来源与版本。QA可以自行补模拟数据、边界值、负例和独立预期；若语义未决可建立多个显式假设profile，给条件化结论。现场事实和正式业务默认不能靠mock批准，也不能阻断与其无关的可执行断言。
9. 同一语义优先复用既有主数据/规则配置，避免CSV、页面、Worker、检查器各自保存一套矛盾值。具体技术结构由Dev决定，本变更不指定框架、接口、数据库或算法。
10. 如果参数确需固定或当前范围不支持，交付说明业务依据、适用范围和后续事项；不能无说明地把示例名、示例数量或唯一排列写成业务真值。

## 本CR补充跟踪的遗漏项

- 共同配置契约在尚无归属的参数上的覆盖；随对应业务包进入，不新增孤立执行任务。
- 日历继承、例外/停机/班次与可中断性的配置完整性：基线有的沿原条款，未覆盖的前台维护和组合语义进入对应包待开工。
- 计划范围/起止、稳定排序、重排保护期、锁定与部分确认的配置完整性：沿FR018/027–030和BR15–17盘点；新增策略待B5/R6/R7相应任务启动。后续优化目标不提前启动。
- 工程运行预算/取消/超时的配置盘点：候选项需Dev说明实际固定点与影响；不预先决定未经讨论的预算默认值，不改变AC27标准。
- P1多线适用与共享配置：挂FR039/040及R8原范围，等待开工；FR041–043、真实系统对接与跨工厂运输不纳本轮实现。

以上“等待开工”是用户要求的计划处理，不是自动派工、平台运行状态或新增用户审批请求。PM登记时须按每项真实来源区分基线已有、已批准CR、新增配置增量和仍待细化语义，不能一律记为新需求或已批准默认。

## 专项验收及开工条件

`acceptance-matrix.csv`记录本CR专项检查，复用原AC/UAT而不改历史条文。每个适用参数至少证明两组合法显式值或选择的差异、非法/缺失/冲突输入处理、新运行实际采用、独立预期、保存重开和旧历史保护。对于不影响业务结果的元数据，以来源/版本/追溯验证代替强行要求排程变化。

参数存在多个合法解时按约束、数量守恒和覆盖判定，不按示例唯一排序。未决业务语义不得通过选择一种profile擅自结案；可以先完成与其无关的验收。

待开工项的输入至少包含：本组业务契约、字段/单位/合法组合、批准与待决边界、可复演模拟数据/独立预期、适用FR/AC/UAT以及对应原任务。缺真实数据不一律阻断允许模拟的阶段；确需正式业务语义的断言只记录精确决定项及影响。

## 业务影响与风险

影响主数据/规则维护、输入冻结、排程与独立检查的一致性、历史兼容、说明/导出及QA参数资产。缺省行为、覆盖冲突、单位换算、多层收率、共享物理身份和旧方案兼容是重点风险。

本轮未评估工时/预算/完成日期，不能写成已批准。技术选择由Dev在对应任务决定。新参数化实现与当前已经通过的限定模拟路径分开收口，避免一次归集把所有在途工作重新阻塞。
