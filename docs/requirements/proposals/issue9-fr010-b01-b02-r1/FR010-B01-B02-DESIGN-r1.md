## 3. B01：授权内澄清与候选规则

### 3.1 可以直接据原义务判定

1. 验收已有显式规则时，使用该运行冻结的状态值、规则、输入和时间；不能事后用候选默认重解释旧结果。
2. 状态不是物料身份；质量可用也不能绕过占用、到达/可用时点、效期、单位和数量守卫。
3. 本轮不改变已通过的合格/待检/冻结/不合格及时间守卫行为；不把代码内置“合格”作为批准依据。
4. 已有批次明细必须可追溯；从一个100kg父批拆出的60/40不能变成父100＋子60＋子40共200kg供给。此为不重复供给/数量守恒，不预先要求实现新的子批模型。

### 3.2 DEC05设计候选（未批准产品默认；未授权实施）

业务分类：CONFIRMED表示该来源在所选规则与时点下具备确定供给条件；CONDITIONAL表示仍依赖明确模拟条件；BLOCKED表示该状态不允许计入。UNKNOWN是缺配置/冲突/不支持的诊断状态，不是第四种可分配质量等级。即便分类为CONFIRMED，仍须通过所有数量、时间和来源守卫。

映射最少表达：稳定状态编码、显示名、业务分类、适用范围、版本、生效/失效、来源与维护依据。编码与显示名分开；不按中文显示名推断规则。具体字段和存储由Dev决定。

候选版本裁决：新运行明确选择可用的已生效配置版本并冻结映射与适用事实；维护草稿不影响运行中或历史方案；变更用于之后的新运行；旧方案重新采用时保留原结果并基于当前事实另行复核。配置按业务有效时间取值，不能在一次运行中途切版本。生效区间拟采用`[起,止)`，时区与时间精度使用明确场景配置；这是候选边界，不能改签现有产品时间PASS。

覆盖方案建议：第一阶段由运行显式选择一个完整策略版本，策略列明适用的单线/物料范围；不引入未定义的产品×产线×工序隐式继承。若业务要求细粒度覆盖，须由计划主管选择覆盖顺序；同优先级交叠或无唯一匹配时不静默选最近记录。建议阻止受影响计算并定位缺项，其他无关查询可继续。此选择补DEC05/F04设计，不宣称全部F04完成。

未知处理建议：拒绝给未知/缺映射/冲突状态计可用量并阻止受影响运行确认，提示状态、批次、来源和所需配置。选择“整次计算阻断”还是“排除该来源并报告缺口、确认前阻断”仍由计划主管决定；未决定前不能据此给当前产品新增FAIL。

预计来源独立门控：建议质量映射与来源类型各判断一次。EXPECTED来源在开关OFF时始终不可用；ON且所有守卫成立时仍为条件供给，即使其质量映射为CONFIRMED也不升级为真实库存。现存库存映射为CONDITIONAL也须保留其明确条件；缺条件不能自动可用。预计转库存须有同源关联与转换核验，不能双计。该候选补F03相关组合，完整预计来源转换流程仍待决定。

粒度建议：质量判定作用于可独立识别且有质量事实的物理库存批/子批，不作用于订单汇总数字。一个父批若没有子批质量证据，不推断子批各自合格。混合质量只能在提供子批ID、数量、位置、质量来源、父子关系后分别判定；父记录是汇总或可用余额须显式选一，不能重复分配。是否允许部分放行、子批继承父状态、隔离区转移、最小投料粒度及拆分精度均需有权人提供规则。没有真实子批数据时可以用单批mock解释，不代造现场分批或放行事实。

## 4. B02：账本所有权、事件与候选契约

### 4.1 三种账的业务区分

| 业务对象 | 所有权与原义务 | 本轮可验边界 |
|---|---|---|
| 输入库存/既有占用 | 库存数据负责人提供有来源、有时点的数量和占用事实；APS在一次冻结输入中读取 | 按已有占用扣抵、不负数、不重复来源；未知占用来源不能再加一份相同预占 |
| 单方案投影 | APS方案拥有该运行分配与预计余额；冻结输入与结果可查 | 试算分配扣抵一次；不证明它改变共享业务事实或仓库库存 |
| 模拟执行事实 | 授权维护人提供模拟任务、耗料及修订；APS保留来源与幂等 | 同一耗料事实一次生效，历史开始/完成/耗料不得被重排抹去 |
| 跨采用方案预占账 | 候选：APS本系统拥有“未执行但已承诺”的内部占用，计划主管确定哪个事件产生承诺 | 基线未定触发器、唯一有效方案范围、存量迁移；待业务批准，不声称当前账已通过 |
| 真实库存/WIP实账 | 实际仓储/生产业务数据所有者负责；具体权威系统尚待事实确认 | P0无外部系统依赖；本轮不授权写WMS/MES，也不把模拟进度当真实发料凭证 |

输入“已占用”若已包含APS预占，必须在对账后按来源拆明，不能再叠加一次。APS预占账和外部/手工占用可以并存，但每个承诺只有一个唯一归属，不设两套互相叠加的同义余额。

### 4.3 数量公式与同源对账

先统一物料与单位，给每个物理来源池定义时点。以下只是可验的候选账模型，不指定数据库或接口：

- `B0`：账期开始库存；`I`：本账期新增且未包含于B0的已核库存流入（不含预计供给）；`C`：本账期生效净耗料（耗料减有证据的误录冲销）；`B=B0+I−C`。
- `O`：尚有效且未包含于R的外部/手工既有占用；`R`：本系统所有有效承诺**剩余未耗**预占；数量意义上的未承诺余额`F=B−O−R`。
- 新的普通分配不得令`F<0`；通过质量/时间守卫的来源才贡献可用量。冻结库存仍在账面B里，其可投料贡献为0；已有承诺标风险。不能简单将质量不可用B从公式删除后伪造账面负数。
- 方案内`P`是针对同一冻结池的一次新增分配；投影未分配量为`F−P`。若输入已有占用已包含该方案承诺，重算时只经明确替换对账处理，不能把自身R再次扣成新承诺。
- 从预占耗用`x`时，`C+=x`、`R-=x`，`F`不变。释放未耗预占`y`时，`R-=y`、`B`不变、`F+=y`。实际耗用`x`后仅`B-=x`而保留原全额R，会双扣。
- 若输入是已包含历史耗用的**当前净库存快照**，使用`B=B_snapshot−C_after_snapshot`；不能再减快照前的累计C。若输入占用是汇总数，来源负责人必须给可核验拆分或核对证明，缺数据时不能猜分。

`O`与`R`冲突、重复事实或快照口径不明时，不截成零、不静默吞掉。候选是停止相关承诺并给出缺口/冲突与来源；现场真实损耗导致的库存不足应保留原事实和短缺，不删历史来凑非负数。

### 4.4 粒度、并发、WIP与历史

候选预占明细至少能回答：哪个数据域/库存池、物料、物理批/子批、位置、单位，哪个方案版本/承诺、订单、实际投料任务/节点，多少未耗/已耗/已释。方案汇总、订单汇总不能代替真实物理批关联。多订单共用一次物理投料时需明示公共投料节点及各订单份额，先物理守恒后汇总；不规定某种唯一排程顺序。

WIP分开表示原料已耗事实、在制品已生成及其剩余可供给量，不把“完成量”直接换成原料kg或WIP净量。各物料投入/损失/产出转换须有批准BOM、计量节点与单位，未确定时只保留原始事实与待核状态。原材料扣耗、WIP形成、WIP后续领用是不同事实；对同一物理物料不得重复消耗，但上下工序对不同物料的合法消耗不误去重。此处不关闭DEC04的F01/F02。

候选并发语义：同一物理池的有效承诺总额受当前事实约束；两个基于旧余额的承诺不能都越额生效。建议每次承诺要么完整成功，要么整个请求零新增写入，并显示冲突与最新差额；如果希望部分采用，需要另行定义部分成功语义。无预定业务优先级时，任一合法先后均可，不用指定某方案必胜。重复同一业务事件返回同一结果；同键不同内容应提示冲突，不再扣/占一次。具体锁、事务、API、事件标识技术由Dev选择。

历史方案只拥有历史输入与结果；当前账不从历史快照恢复。迁移时区分“已确认但尚未定义承诺含义”“已经输入在占用中”“已耗事实已计净库存”的方案/记录，给出处置清单，业务确认对账后才启用承诺。不能将所有历史确认计划直接生成R、再把所有历史耗料从当前净量重复扣除。
