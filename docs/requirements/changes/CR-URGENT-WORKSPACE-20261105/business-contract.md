# CR-URGENT-WORKSPACE-20261105｜插单独立入口与策略、影响追溯升级

版本：R1，2026-11-05。提出人：APS-Design；管理与调度：APS-PM。

用户原话：“把其中插单的功能原型作为CR提交，并在github上创建任务，在主程序已有的插单能力上修改；请把插单作为一个单独功能，抬头栏位点击进入”。

本次选定此前五任务原型中的E01，升级主程序已有插单功能。一个CR对应一个完整业务任务；其他E02多方案、E03滚动仿真、E04目标优化、E05标准修正不纳入。插单涉及的故障、质量事件用于解释和修复当前计划，不扩建通用事件平台。

## 2. 入口与页面分工

主程序抬头栏增加与“排程流程”同级的 **“插单”**。点击进入独立的插单工作页面，建议排列在“排程流程”之后。独立指业务页面与导航入口，沿用现有APS数据、服务、存储、权限、计算与计划采用机制。

1. 进入页保留当前数据集、业务版本、配置修订、已选生产计划/run、窗口和观察时点；页首始终明确基准/候选/当前事实身份。没有选定计划时可进入页，显示“请选择已保存的生产计划”；提交、生效、排程、采用等动作不可用并说明原因，不能默建新计划或用空计划替代。
2. 进入、返回排程流程、再次进入均不触发导入、生效、计算或采用。已生效批次、保存候选与历史结果能重开；未提交编辑切换前明确保存或放弃，不静默丢失。
3. 原工作台位置若保留快捷入口，应转到同一“插单”页并带入同一计划，不保留两份独立状态或重复完整编辑区。
4. 页面采用“事件与插单 / 策略与影响 / 设备甘特 / 批次追溯”分工；策略与影响保留原合同的“插单结果 / 原需求影响 / 工序与资源变化 / 未排与原因”四类业务视图。额外来源信息通过抽屉或次页签呈现，不替代原四类信息。

## 4. 数据、参数及时间语义

- 统一参数页与插单页就近入口使用同一参数对象、校验、范围、有效期及修订；第二份P配置文件的定义、边界、缺失处理和同对象有效值优先。明确区分持久配置与仅本次候选覆盖，任何入口修改均使旧就绪检查和相关候选失效；旧run不变。
- 观察/事件发生/可知/生效、冻结截止、半冻结截止、故障恢复、加班起止为日历分钟；生产开始/结束、净剩余、清洗/等待、资源占用均保留整数分钟，甘特30分钟只作刻度。需求/库存/补料业务日期仍按天，当前仿真默认查询2026.11.01—11.14。
- 截止关系为观察时点≤冻结截止≤半冻结截止；任务区间为半开区间。已开工/已完成保护优先于分区；故障例外需显式记录适用任务/属性、原因及修订，不解除已发生事实。无适用有效配置时显示缺项，不能猜2小时或把0误当已确认。
- 加班须明确合格资源、日历日期与起止、人员/工装配套容量；开启策略不等于已获得资源。故障恢复时点与确认状态分列；无恢复资料返回待处置。放行/运输/待料边界引用实际参数，不将原型12小时或2天作为默认。
- 数量必须保留需求单位、包装换算、生产单位及批次数量来源；只对同单位可比项汇总，不以SKU数代数量。替代可用量=合格且有效的在库量−不可挪用占用；最多替代未投料量，不重复占用/扣料。放行只改资格，不再次增加实物。
- 来源需列文件/表/原行/业务键、实际投料关系、计划/run、输入/P/事实/策略指纹；没有实际批次记录则明确“关联未知”，不能按BOM推断全部受影响。实际受影响与仅BOM展开两种关系分别标识。
- 候选/影响/甘特/导出/重开用同一冻结版本。请求与实际求解器、停止原因、独立检查结论可追溯；超时、取消、未排、能力缺失、业务不可行分别解释，不以工具超时判业务无解。

共用UI沿V2：紧凑字体与间距、搜索多选初始/重置全选、明确清空；每表及图形视图的栏位控制；分层明细溯源；100/200/500分页；全量筛选排序/导出；日历日期；有效BOM递归去重只改变显示、不增需求或扣库存；不新增讨论意见入口。
