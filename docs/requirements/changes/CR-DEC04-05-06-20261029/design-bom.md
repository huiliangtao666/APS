# DEC-04：BOM、损失与取整设计

## 1. 数据与配置

复用产品、物料、BOM、工序、库存及订单主键。新增策略以`policy_id/version/effective_from/effective_to/scope`引用，不再复制物料余额或产品重量。金额、食品配方优化和真实采购不在本设计范围。

| 参数组 | 核心字段 | 维护与校验 |
|---|---|---|
| 配方基准 | `basis_kind=INPUT/GOOD_OUTPUT`、`basis_quantity`、`basis_unit` | 基准量>0；与物料定额单位有合法换算关系 |
| 收率路径 | `yield_mode=TOTAL/STAGED/INCLUDED`、`total_yield`、`stage_yields` | 收率(0,1]；TOTAL与STAGED互斥；INCLUDED不能再次除收率 |
| 损失归属 | `loss_inclusion=INCLUDED/EXPLICIT/NONE`、`loss_fraction`、`loss_stage` | 只能作用于明确物料/工序；包含与另计不得重复 |
| 量化 | `quantity_quantum`、`rounding_scope=ORDER/BATCH/OPERATION`、`rounding_stage` | 粒度>0；与单位维度一致；保留量化前数值 |
| 包装 | `pieces_per_bag`、`bags_per_box`、`partial_pack_policy`、`pack_loss_mode` | 换算量为正整数；尾包明确允许或拒绝；损坏率[0,1) |
| 展示 | `display_scale`、`display_rounding` | 只影响显示，不能反向改变分配和缺口 |

枚举是设计候选契约，技术实现须明确支持清单。前台显示每个参数的来源、单位、继承及是否待确认；不把示例值设为所有产品的固定业务规则。

## 2. 计算顺序与解释链

1. 按订单剩余合格需求及选定产品/路线冻结版本确定目标量，已有完成和实际耗料沿用执行事实保护，不能重新当作未使用库存。
2. 将目标量换算到BOM基准单位。只有INPUT基准且尚未包含收率的路径需要从合格量反推投入；GOOD_OUTPUT且损失已含的定额不再重复放大。
3. TOTAL路径：`投入=目标合格量/总收率`。STAGED路径逐节点反推，`总有效收率=各节点收率乘积`只作解释/一致性校验，不能再同时套产品总收率。
4. 每条物料行按其基准、定额及投料节点求精确需求，再应用该项明确另计的损失或加入量。损失采用“损失占毛投入比例”时，`毛需求=净需求/(1-损失率)`；若业务采用“相对净需求加成”，必须选择不同模式并明确公式，不能混称一个损失率。
5. 按所选层级执行一次业务量化。保存精确量、量化量和差额，采购建议可另行向上取整，但不能把采购整包量记成已消耗量。
6. 按投料时间、可用性及分配规则分到实际批次，汇总检查订单、生产批、物料和批次守恒。剩余误差必须有明确残量分配记录，不能消失或重复向上取整。

每个结果行至少携带订单/生产批/物料/投料工序、BOM及策略版本、原始基准量、收率/损失来源和应用次数、精确需求、量化差额、分配和缺口。

## 3. 基线推导示例

UAT-09产品HC40目标240kg、总收率0.96、每1000kg投入的LEAN/FAT/WATER/PREMIX定额650/150/150/50：

- 投入`240/0.96=250kg`；物料分别`162.5/37.5/37.5/12.5kg`，合计250kg。
- HC40每支0.04kg，因此为6000支；每袋10支，损坏0时需600袋。袋数与原料投入不是同一计量基准。
- LEAN-EARLY账面137.5kg、已占用37.5kg，净可用100kg；LEAN-LATE62.5kg，合计162.5kg。冻结及过期999kg批次不补数。
- UAT-10把后批改为62.4kg，净缺0.1kg。显示精度、容差或修改库存筛选不能把它变成“齐套”。

这些数字来自受控mock，不是现场配方批准。

## 4. 拆批、尾包与精度边界

仿真例：两个生产批各精确需要0.104kg，粒度0.01kg。若明确按批向上量化，总量为0.22kg；若明确按订单汇总后量化，则0.208→0.21kg，再进行可追溯分摊。两种业务口径须由配置区分，不能用批处理循环顺序决定。

仿真例：101支、每袋10支。允许尾袋不足时需11袋，产出仍为101支；禁止尾袋时给出尾包问题，不自动生产110支。包装损坏选择净需求除留存率时，10袋有效需求、损坏20%对应毛量`ceil(10/0.8)=13袋`；不能误用`10×1.2=12`。

计算使用十进制定点或精确分数，跨单位换算保留原量和换算版本。离散单位的物理粒度由单位配置约束；显示舍入不决定业务可用量。库存按每次实际分配扣算，不独立对每个批次再次取整。

## 5. 错误与验收

收率为0/负数/>1、损坏比例>=1、基准缺失、单位不兼容、版本冲突、损失重复路径、缺投料工序、禁用模式或不合法包装量均不得启用。显式0损失合法，空值不自动等于0。

后续必须独立验证：前台改收率/量化层级→保存刷新→新运行需求变化；计算来源可导出；非法保存原子拒绝；冻结旧版本不变。`check_mock.py`只核对本文件数值与数据一致性。
