# DEC-06：可配置工艺与系统联动设计

## 1. 版本化配置对象

沿用产品/产线/路线/工序/设备/程序/资源主键。策略通过`policy_id/version/scope/effective_from/effective_to`引用；需求与资源声明不能出现两套相互覆盖的“真实容量”。基础数据与覆盖项在前台显示来源和优先级，同优先级冲突阻止启用。

P0仍采用可维护的顺序路线；MIX/FILL/HEAT/COOL/PACK仅为mock名称，不是内置生产步骤。其他工序名称及数量可以由数据定义，但不因此批准任意并行分支、跨厂或多线优化能力。

## 2. 工时及效率

| 模式 | 计算方式 | 必需配置 |
|---|---|---|
| FIXED | 固定程序时长，不因未满载变短 | 固定分钟、程序及适用工序 |
| RATE | 参与计量的数量÷有效速度 | 产品/设备/单位、计量节点、速度及时间单位 |
| RATE+效率 | 名义速度×效率得到有效速度，再算工时 | `rate_basis=NOMINAL`且效率(0,1] |
| 已实测速率 | 直接使用已含效率的速度 | `rate_basis=EFFECTIVE`，不能再次折减 |

不允许把“固定分钟”和“速度”同时相加，或因CSV中存在速度字段就忽略明确选择的固定模式。实际计算保留精确时间，展示精度单独设置；缺速度、0速度、不兼容单位和不支持模式不得启用。

源UAT-12：HEAT固定120分钟，HEAT01最大500kg；HC40/HC60的PACK为按支数，速度分别120/100支每分钟。1200支对应10/12分钟。若mock把HC40改为名义120、效率0.8，则有效96、时长12.5分钟；若已给实测96，不能再乘0.8得到15.625分钟。

## 3. 容量与组批

装载量必须声明计量节点：BOM总投入、指定工序在制、合格产出或显式单位量。240kg合格品在收率0.96时对应250kg投入，不能拿240与按投入配置的设备容量比较。

最小/最大装载、允许拆分、尾批不足处理、程序/配方/路线兼容条件和固定程序时长均为配置。每个资源批保留原生产批/订单身份及数量；总量不因合并或拆分改变。禁止自动超产补满，未满载的固定程序仍运行完整时长。

允许列表包含TP-HC40和TP-HC60表示该设备能分别运行两种程序，不等于两种程序可在同一个资源批混用。兼容分组另有明确配置；不能把程序名相似当成兼容。

## 4. 等待、冷却与空间

等待参数以相邻工序的真实结束/开始时刻为锚点，记录最短与最大允许值及边界。冷却/暂存声明占用量的计量节点、资源单位、开始锚点、持续时间和释放锚点；与人员/工装策略共用来源规则但不混淆物理池。

mock采用半开资源区间并明确最大等待包含等于边界。源UAT-12的HEAT→COOL最大等待10分钟，COOL固定60分钟；COLD容量480kg。源UAT-14的COLD实际为400kg，不能误套480。两笔各240kg若冷却重叠，480>400，必须改变上游安排或报告无可行安排。

单任务占用量已超过空间容量时，单纯推迟时间也无法解决，必须明确未排/调整建议。最大等待与下游空间不满足时不能仍把上游任务视作整体可行，也不能改写已执行事实来“腾位置”。

## 5. 方向性转换

换型/清洗记录来源产品或程序、目标产品或程序、设备/工序、时长、人员/空间需求及适用期。mock可配置A→B为10分钟、B→A为25分钟，二者是独立数据；同产品转换若需要0也须有明确默认策略。必需转换缺配置时显示未知/不支持，不能默认为0。

## 6. 前台、接口与持久化

前台按“BOM与数量”“质量与供给”“工艺与资源”分组展示，复用已有数据维护入口。提供中文名称、枚举选项、单位、引用选择、继承提示和小样例计算预览；普通用户不写公式代码或原始JSON。

配置接口沿用现有版本/权限/原子保存契约，新增对象须显式列入数据字典和CSV模板；草稿与启用版本分离。请求包含预期版本、修改原因与策略引用，服务端拒绝越权、版本过期、同级冲突或非法关联。新运行保存配置版本/散列、计算口径、实际生效时刻及来源，Worker和独立检查器使用同一冻结事实但独立验证，不信任结果自报标签缩小检查范围。

mock策略文件是待实现的设计契约。当前应用没有该导入/执行接口的交付证据，本设计不虚构一个已经存在的API路径，也不以保存了新字段就宣称业务生效。

## 7. 迁移与独立验证

先盘点既有字段：总收率/计量基准/损坏比例、规则参数JSON、固定/按支数工时、单位与容量、批次质量/时点、空间和路线。迁移策略明确兼容口径，原字段不悄悄改名或改变含义；缺新语义的旧配置显示待确认，不静默推导现场值。

独立验收须覆盖前台保存刷新、版本冲突、参数改变后实际运行差异、独立物料/资源复核、冻结历史保护和同源导出。mock检查器只证明示例来源与预期算术，不能替代这些验收。实施限于本CR明确范围，Dev仍先处理已有Test失败。
