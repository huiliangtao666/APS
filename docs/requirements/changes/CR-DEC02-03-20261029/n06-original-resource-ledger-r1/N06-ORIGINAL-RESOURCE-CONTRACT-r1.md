## 5. 已知有限区间、未知释放与容量判定（F06/F07/F12）

所有时间使用原事实时间原点、时区和既有分钟精度，冻结换算规则；更换新运行原点时仅做可逆坐标换算，不能把历史开始改成新运行开始。资源采用半开区间 `[s,e)`，边界 e 不再扣原占用，同点可以取得新资源。事实数量为q，则原占用 `L_fact,p(t)=Σ q_i·1[s_i<=t<e_i]`，按稳定物理池p和去重后的实际占用身份求和。人员另检查组资格上限，工装和空间按各自单位，不跨单位相加。

新候选须满足每一相关时间片 `L_fact,p(t)+L_plan,p(t) <= C_run,p(t)`，同时满足当前适用日历/技能/可用期、物料和其他已启用条件；原事实本身不移动。真实共用占用只计算一次，多成员关系用于追溯。旧已确认计划中已执行的对应预留必须有明确原任务/占用关联去重；不能把计划预留和已实际占用再扣两遍，也不能删除其他尚未执行的有效预留。无法确定同一性时阻断该冲突解释，不能任意舍弃一项。

- **已释放且完整**：过去完整区间保留；与新试算域有交集时按真实区间保护，不按当前后延重算。`e<=新试算下界` 的原占用不占未来容量，历史账继续保留。仍要保护机器/已完成产出等已有事实，资源已释放不等于任务未执行。
- **未释放/暂停但起点和实际量已知**：观测点证明“当时仍占用”时保留该事实状态；释放时点未知。可显示已知历史占用及未知结束标记，禁止填0、无限值、任务完成或剩余投影作真实结束。任何依赖该实物/池未来可用量的正向试算和确认都 BLOCKED，不能仅因计划将占用推迟到某时就称已释放。新运行有限H只是查询边界，不能当真实释放。保守展示到H也只是风险覆盖，不是有限原账通过。
- **暂停但已实际释放某项**：该项有释放原件可进入有限子范围；其他未释放项继续阻断。任务暂停既不自动释放人员，也不自动持有已退工装。恢复所需资源属于新的未来需求，按冻结规则安排，不能改变旧资源区间。
- **量/身份/起点或完整性未知**：不能仅阻断某一行后忽略继续算；凡无法证明独立于缺项的物理容量域都不可声称已检查。可以继续保存不相关草稿/查看旧方案；只有已证明资源域和其他依赖独立的子运行才可另行判断，不能把未知资源默认“不相关”。
- **未选订单**：选择订单仅裁剪新需求，不裁剪既有执行保护。全范围原账、采用清单、原映射和必要供给身份均冻结；未选A的实际占用与选中B同池仍参加容量比较。关闭当前规则、隐藏旧组/声明、只选其他订单都不能释放事实。

已实际释放不等于同任务未来不再需要资源。正在进行/部分完成的任务若有明确剩余需求，未来申请独立于历史占用，不能以剩余工时重锚历史窗口。原占用仍未释放且与未来需求可能同一实物时不双计、也不当成新可用：须原件/契约明确连续持有关系，否则未知结束路径阻断。首批有限子范围优先原任务已完成或资源已明确释放、无这种重叠歧义的输入。

未知释放的未来可计算正向能力仍 BLOCKED；解除由该资源事实负责人提交真实释放事件，或补足另行批准且可判定的未来保护契约。这里只给保护/诊断守卫，不批准一律全时段占用或任何未来释放预测。

## 6. 追加事件、冻结和确认保护（F10/F11）

原账和事件只追加；“当前有效视图”由指定事件版本重建。Dev可选择版本ID、hash、幂等键、存储和审计实现，不需用户替其选工程方案。

| 事件 | 必需证据与校验 | 历史与当前效果 |
| --- | --- | --- |
| 首次取得/参与 | 完整来源、稳定占用身份、原任务批映射、原规则、实际q/s；释放状态明确 | 形成原账；有缺项的草稿不能进入“已完整可计算” |
| 追加释放 | 引用原占用和当前有效事件修订、释放原件、真实发生时间、观测时间、采集原因；本有限切片只支持该笔全部q释放 | 原未释放事件保留；新有效视图成为[s,e)。不能按新配置推e；不能重复释放增加容量 |
| 纠正 | 原责任方证明原录入错误、明确替代哪一事件/字段、前后值及原因；有权主管核对；引用链无环且无分叉冲突 | 原事件仍可查，新版本重建正确视图；纠正实际量不是另加/另减一笔领退，不同时保留原量和新量扣账 |
| 重复/过期 | 同来源同事件原样重送幂等；同标识不同内容提示冲突；针对旧修订的并发追加拒绝整次写入 | 无重复累计、无部分来源/审计写入、无静默覆盖 |

真实后续释放是状态演进，不叫“改错”；纠正是更正错误证据，不表示实际发生退还。首批只支持单笔全部释放、单一连续实际窗口；部分退还、分次取得、实际量随时变或再次领用的表示需单列，禁止用拆行偷偷扩展到同工装多不连续窗口，也不把不同实际领用强行合并为一段。真实事件可以保留待核材料，但不得假装当前有限模型已完整计算。

每次新运行冻结：原累计事实修订、原任务/批映射、实际采用清单、逐占用和事件截至序列、历史规则/组池/技能/班次及来源版本、去重关系、当前供给与启用规则、完整性状态、观测点、时间原点和输入指纹。Worker按冻结输入运行；独立检查器从同一冻结原件/事实事件和来源关联重建，不能读当前配置替代，也不能信结果自报“资源已释放/完整/poolId”。删账、少量、错池、改端点、去掉未选订单、用当前规则替换原版本都须检出。

新增释放/纠正后，旧run/已保存方案/确认快照和原始账字节保持。新运行采用新有效视图。打开旧方案仅展示其当时冻结输入；尝试恢复/再次确认必须按已有保护契约核对最新事实与版本冲突，不恢复旧事实覆盖当前。并发事实更新使待确认输入过期时原子拒绝确认并提示重算；不因只是“释放了更多容量”就跳过重建。旧已确认的记录不改写为已通过N06。

**确认计划与实际执行界线**：计划员/主管确认某方案只形成计划承诺/预留，不能自动生成实际采用资源账。实际取得/参与由有权事实提供方给原件，计划员/主管采集核对后才成为执行事实。原确认快照可引用为当时规则与计划关联证据，不能单独证明数量/释放。若实际偏离计划，实际值和偏离原因独立记录；不回写原确认计划使其看起来一致。执行事实纠正使旧确认与最新事实冲突时给风险/重新核对状态，保留旧确认；本任务不创建全局预留/发布新语义。

前台沿既有维护/查询权限提供中文录入与读回：原事实/原批关联、逐资源q及单位、取得/释放/未知状态、原规则与原件位置、提供方/采集者、采用清单与缺项；预览真实区间及完整性，明确“草稿待核/可计算有限账/未知释放阻断/过期冲突”。保存刷新/重开读回同版本；查询角色只读，可信actor/时间/原因/版本沿既有契约。非法、越权、未知引用、过期、重复冲突、不可表达组合均按原子失败处理。原dependencies非空事实409保护继续保留，不以本原账写入绕过它；如实现需改变该保护，先明确相关已授权行为和影响交PM核对，不能静默删除。
