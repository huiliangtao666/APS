## 实现路径

`InputData` 的选定保存运行 → `UrgentOrders` → `/workbooks/urgent/*` → 原 workbook 状态仓的 `urgentPlans` / `runs` → 原 `calculation-worker` → `calculateWorkbook` → `verifyMinutePlan` + `verifyUrgent` → 同源影响查询/全量导出。

计划上下文绑定原 run、输入指纹、原需求集合、窗口、明确执行事实、批次及修订。只保留原计划实际纳入的普通需求，不把数据集中其他计划需求混入；计算时不允许通过临时 demandIds 缩小范围。每个批次只追加此上下文，原数据集和旧运行不改。

Excel 入口只消费每日需求页。单页与整本采用同一解析器的选页模式，保留第2行17列、第3行起数据；其他页不解析为业务更新。五个业务必填字段不接受公式；缓存不覆盖同版本物料、客户及 P/在线有效参数。错误包含页/原行/字段；原子生效、预览凭据与版本比较、批次重试及 ID 拒覆盖在同一同步状态写入中完成。

执行事实逐任务明确状态、实际起止、合格量、人员参与和工装释放；逐分配明确实际已耗/已交付/锁定量及时间，已完成量与成品耗用相符。不从计划按比例推测实际投料。不明确的执行/耗料会拒绝运行；WIP 原物理保留及净账继续复用原输入。已执行事实不能回退、锁定不能自动释放。

普通未开工工作与所有插单一起进入原分钟主程序。插单优先，其内部采用客户优先与交期，再按生效序号、需求编号稳定排序；普通订单仍保持原遍历次序。每次扣除实际完成与不可挪用的已有覆盖。部分可行数量用有限候选搜索并独立检查，剩余量和失败候选依据明确保存，不承诺全局最优。未受保护在制续作按需要取用；初始物理占用始终保留。

保护时段及客户服务优先级方向沿同一参数入口维护：`GLOBAL / 重排保护时段`（分钟，允许显式0）和 `GLOBAL / 客户服务优先级排序方向`（枚举“数值小优先”/“数值大优先”）。二者不设置产品默认，不修改原 P 候选。CP047 原定义要求说明排序方向，因此缺方向不能猜。该接线不代表现有数据已具备值，运行准备必须核对所选 P 的实际值和批准来源。统一页与步骤页共用原参数 API。

新任务不早于观察/生效时刻。实际已开工/完成任务保持事实，既有锁定及保护时段内任务保持位置。独立检查从任务与输入重建资源、人员、工装、清洗、前序、效期、日量、供给累计使用、生产批次时间资格和净需求守恒；历史已完成产出不因补做剩余量而重复生产或等待新批次完成。

四页签包含全部原需求（含未变化）、插单结果、业务工序谱系及未排/WIP续作原因。资源直接占用与前序释放链有任务证据；不能证明直接因果的差异明确标为重排差异。事实、参数及供给分配变化分列。新增插单任务不计原任务变动，统计按需求去重，数量按单位展示。
