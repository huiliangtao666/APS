## 实际实现

- 查询来源 JSON 使用小子树原生序列化和有界 hash 分块，保持键序、UTF-8、缺失值/数组洞等既有 JSON 语义。大树继续流式遍历，不同时保留完整序列化工作簿。
- 来源复制直接构建隔离对象节点，保留 `__proto__` 自有数据及全部来源字段。
- router 内 gzip 快照 LRU：最多8项、合计32MiB未压缩输入字节；plain state 缓存：最多1项、12MiB输入字节。两个上限衡量输入字节，不冒充实际对象堆大小。超限数据仍完整读取，只不保留缓存。
- 每次读取 stat 校验 dev/inode/size/mtimeNs/ctimeNs；覆盖、原子 rename、删除、损坏均失效/拒绝，未发现可用旧值回退。读取期间身份变化拒绝。state/meta每次选定真实版本或P workspace，再读取对应ref；没有跨计划/版本/actor的查询结果缓存。每次返回深层隔离节点，变更只经既有保存路径。router退出即释放缓存。
- 冻结 inputs 响应复用同请求已校验输入，消除第二次读取。既有权限和冻结 hash 校验不变。
