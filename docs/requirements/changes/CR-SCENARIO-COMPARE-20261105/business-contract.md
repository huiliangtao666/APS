# CR-SCENARIO-COMPARE-20261105｜多方案试算比较

版本：R1，2026-11-05。提出人：APS-Design；登记与调度：APS-PM。

用户原话：“多方案试算比较的功能原型作为CR提交，并在github上创建任务。”

## 1. 变更目标与依据

将五任务原型中的E02作为独立完整功能提交CR。在主程序已有保存、复制、条件试算、真实求解、独立检查及计划采用能力上，增加“同基准建多个情景→批量试算→指标并列→差异追溯→选定方案”的完整链路，一个GitHub任务承载，不拆成字段或页面微任务。

当前范围基线为APS-BL-002 / V2，入口 `docs/requirements/active-baseline.json`。主关联FR-026保存复制比较、FR-028条件试算，相关FR-025独立检查、FR-030确认归档、FR-032/035查询与解释；验收关联AC-20/26/32及适用的UAT-15/17。新增多情景与统一口径作为V2后增量，原条文和历史证据保留。

业务设计来源为《APS能力演进_需求与功能设计_V2配套_R1_20261105》E02-F01—05及E02-A01—06；交互依据为 `APS能力演进交互原型_20261105_R1/E02_多方案试算比较.html`。

已有条件试算关联任务[#47](https://github.com/huiliangtao666/APS/issues/47)顶部记录为固定版本功能阶段Done，外部入口和最终业务UAT未签；本次不重开原卡、不迁签本次功能通过。插单升级[#155](https://github.com/huiliangtao666/APS/issues/155)是独立任务，复用已具备接缝，不要求其全部完成后才设计或登记本功能。E01插单、E03仿真、E04目标优化、E05标准修正不随本卡整体启动。

## 2. 页面与完整业务范围

在主程序提供独立“多方案试算比较”功能页，可由已保存方案进入并带入基准，回到原方案不改变原计划。页面沿原型分为“情景条件 / KPI并列比较 / 需求差异”；任务、资源、批次与来源用抽屉/明细分层展示。没有选定可读基准时提示选择，不能默取最新数据冒充原方案输入。

| 功能 | 完整要求 |
| --- | --- |
| SC-F01 情景创建与条件维护 | 同一基准复制多个独立情景，保留情景名称、编号、基准、变更对象、旧/新值、单位、适用范围/日期、依据及修订。首轮覆盖加班、人员增加、采购预计到料延期；支持一情景维护一组显式变化、撤回及校验，其他既有条件类型按现有已批准能力复用。变更仅为试算覆盖，不直接修改业务/P或真实执行事实。 |
| SC-F02 批量试算与生命周期 | 勾选多个情景，一次提交，分别排队、检查、真实计算、保存、失败/取消。单项失败不污染其他情景，可继续其余项；停止剩余试算保留已完成结果。业务批量不强制多个求解进程同时运行。失败、超时、取消、未排、未知与模型不可行分别展示，不用基准结果填充失败情景。 |
| SC-F03 统一KPI并列 | 固定对比范围与指标定义，并列基准及候选的准时率/覆盖、迟交、未排、累计延期、原任务变动、资源负荷、清洗/加班、缺料及临期风险。可显示相对基准改善与代价；金额仅在已定义范围/费率及启用条件齐备时计算。 |
| SC-F04 差异与原因下钻 | 指标点击定位同范围需求、稳定任务/生产批谱系、资源、物料批次及变更来源。包括未变化原需求；解释直接与连锁影响、未知和瓶颈。增加非瓶颈人员可无改善，不能为每次变更虚构收益或把全部差异归因单一条件。 |
| SC-F05 选定、采用与归档 | 保存对比组、情景条件、结果、偏好与说明；用户选定后复用既有计划核对/采用流程，采用前重核当前事实、输入、配置及候选条件。生成新版本，放弃不影响原方案；不自动采用“指标最高”。保存重开及全量筛选导出保持同一来源与口径。 |

## 3. 同基准、隔离与计算规则

1. 对比组固定基准run、业务输入、基础P及在线修订、执行事实、观察时点、窗口、规则/目标定义、计量/时间原点、求解器条件及预算来源。情景显式试算覆盖属于本组允许的差异，不能把有记录的加班/人员/到料变化误判为混基线；底本或指标定义不一致则另组，不能标为公平同基准比较。
2. 冻结底本，分别保存每个情景的覆盖、输入指纹、实际引擎/规则、检查与结果。复制不能使情景间共享可变对象，试算条件不写回库存、采购、班次、主数据或P。物料、合格设备、人员技能/班次、工装、空间、工序顺序、清洗/放行及执行保护等适用约束仍真实成立。
3. 加班须有日期、起止分钟、资源资格与配套容量；增人须有班组/资源/技能、人数和有效班次；到料延期作用于明确预计供给批次及业务日期，不伪改已收货事实，也不默认为供应商新增供给。变更缺失、越界或能力未支持需定位字段/对象，不能只改标签后展示原结果。
4. 基准输入/P/事实变化时，旧组与结果留存并标过期；用户可查看旧组，明确重建到新组后重新试算，不覆盖旧版本。情景条件或适用计算规则变动使该情景旧结果失效；采用前再次核对，不能仅依赖打开页面时的检查。
5. 求解器请求与实际引擎、预算及取消/超时状态沿现有机制；不借此新设优化目标或CP-SAT默认，不把换引擎作为本卡必须新增条件。多个已选情景按有效运行容量排队，重试有独立尝试身份，不能重复创建/采用同一请求。

## 4. 指标口径、参数与页面规则

| 指标 | 本次合同口径与缺失处理 |
| --- | --- |
| 计划准时率 | 固定筛选内有效到期需求集合N，按原交付节点/客户到货窗判断全量需求是否已覆盖且按期。准时条数/N；未排、部分未覆盖及结论未知不当准时，不从分母悄悄移除。同时列未知数、结论覆盖率；N=0显示不适用。这是计划预计交付口径，不是实际履约率。 |
| 迟交/未排/未知 | 可判定预计交付且晚于要求为迟交；未覆盖的需求及数量分别列出，原单去重，部分未排明确标记。未知单列并说明缺失字段。需求条数、任务数及不同SKU单位不能混为一个合计。 |
| 累计延期 | 只对可计算的预计交付与要求日期按天计算max(0,预计−要求)，明确覆盖范围；未排/未知不填0天，另列其条数和未覆盖量。阶段/日内截止沿现有有效定义，不猜未知放行时刻。 |
| 原任务变动率 | 使用同一可比原任务集合T；时间、合格资源、适用分配或状态有变化计一次C，C/T。新任务不加入原分母；原任务拆合沿稳定谱系合并判断，不重复计；移除的原任务明确计变动及原因。T=0不适用，谱系缺失标不可比。 |
| 资源、清洗及加班 | 同一窗口按资源/单位列实际计划占用与有效可用容量；负荷口径包含适用联合资源约束，不能混合台、人、空间单位。清洗按实际有向换型任务计且不重复加准备；加班按显式额外可用窗口内占用分钟计，保留明细来源。 |
| 缺料及临期 | 按物料/批次、数量单位、日期与资格列缺口、受影响需求及临期风险；不跨单位加总，不把质量未知当可用，也不把预计报废等同已扣库存。 |
| 成本/金额 | 仅对已启用、定义完整的费用类别，按有效日期、币种、对象、数量基准和费率计算。缺费率显示未知，部分费用只称“已知项目小计”，不冒充总成本或参与总成本优劣排序；费用定义修订保留旧分析，不改旧生产run。 |

同组共用指标定义、筛选及分母，任何数字、图表、明细、分页和导出须一致。没有改善是合法结果；不得固定承诺加班/增人必然提升准时率，也不得据演示值预设排序。

新增信息只在需要时显式配置：情景可比较上限、排队/运行容量与预算来源、条件对象/单位/作用期、对比窗口、KPI定义/分母、可比任务谱系、成本启用类别/币种/费率、生效范围及候选失效规则。注明类型、单位、合法范围、覆盖优先级和生效点；尚未提供则显示缺项/未知。原型“最多5个”、0—30整数条件、2小时、2人、延期2天、120元/小时均是仿真范围或样例，不自动成为系统上限或现场默认。生产条件正式支持整数分钟，不被小时演示输入限制。

数据/P语义沿V2及第二份配置文件优先原则；统一参数页与就近入口同源。本次情景覆盖与共享参数维护明确分开，未经明确采用不写入共享P或业务版本。

页面沿既有APS规范：12px紧凑字体、28px常规控件及已有间距；筛选框内搜索多选、初始/重置全选，清空为无结果；各表/图/抽屉独立栏位与来源下钻；100/200/500分页；筛选排序汇总/导出基于全量结果。需求/库存/补料用日历天；生产计算保存到分钟、甘特30分钟刻度且17分钟不取整；当前仿真默认2026.11.01—11.14。有物料筛选时支持有效BOM递归去重，只扩展展示，不改变实际需求/投料/合计。无讨论意见入口。

## 5. 验收断言与独立算例

SC-01—18是同一完整任务的验收索引，不另立18个任务。覆盖原E02-A01—06，实际产品按固定版本记录预期、实际、证据及未验；复用旧FR/原卡证据只限未变范围。

| 编号 | 操作与预期 |
| --- | --- |
| SC-01 | 由已保存基准进入情景页，显示完整底本/事实/窗口身份；无基准明确提示；进入不计算、不修改原方案。 |
| SC-02 | 新建基准、加班、人员、到料延期情景并维护一组条件；旧/新值、对象、单位、有效期和来源完整，可撤回；每份与原输入及彼此可变状态隔离。 |
| SC-03 | 明确情景覆盖允许差异；混入另一底本/P/事实或不一致指标定义被拒或另组，不能标成同基准公平比较。 |
| SC-04 | 勾选多个情景一次提交，分别排队/真实计算/保存；实际引擎、预算、检查和终态可追；不以标签或原基准重贴代真实计算。 |
| SC-05 | 单项失败/超时不污染另两项；取消指定排队/计算项及停止剩余项保留已完成结果，取消竞态不将已完成结果误写失败；超时不判业务无解。 |
| SC-06 | 保存后重开能恢复组、条件、排队/取消/失败的真实终态、已完成结果及来源，重试有可追尝试身份，不重复采用。 |
| SC-07 | 固定有效到期需求10条：8准时、1迟交、1未排，计划准时率80%、未排1条；未排/未知不被悄悄删出分母或写0延期。 |
| SC-08 | 4个可比原任务中1个变化，变动率25%；新增任务不提高原分母，拆合按谱系去重。不能证明对应关系时明确不可比。 |
| SC-09 | 相同物料/设备约束下只增加非瓶颈人员，允许交期无改善并解释真实限制；不虚构收益或保证加班一定改善。 |
| SC-10 | 交期/未排/延期/变动/负荷/清洗加班/缺料临期指标可下钻同口径需求、任务、资源、批次及条件；原需求包含未变化项，直接/连锁/未知原因分列。 |
| SC-11 | 缺费用资料显示未知，时间指标仍可用；显式加班2小时、费率120元/小时，则此加班费用240元，不当完整总成本。 |
| SC-12 | 加班资源/配套资格、人员技能班次、物料供给与效期质量、工序顺序、清洗/放行和已执行事实均按当前有效规则检查；不为比较放松硬约束。 |
| SC-13 | 底本/当前事实更新后旧候选可查但不可直接采用；重建新对比组保留旧结果，条件修改只失效相关结果，不覆盖历史。 |
| SC-14 | 选定候选后再次核事实/输入/P及独立检查，沿既有确认流程生成新版本；放弃不改变原确认计划、不还原过时库存或抹执行事实，不自动选择最高分。 |
| SC-15 | 默认/重置全选、搜索不丢隐藏勾选、明确清空；逐表栏位和100/200/500有效；筛选、排序、KPI、明细、全量导出同范围同单位，不只统计当前页。 |
| SC-16 | 生产17分钟在条件/真实计划/详情/导出保持17分钟，30分钟仅展示；需求/采购/库存按日历天，未知日内边界不猜值。 |
| SC-17 | 对比组和每个情景冻结实际输入/P/覆盖/规则/引擎/预算/结果及来源；第二份P优先，情景覆盖不改共享配置，保存重开/导出不漂移。 |
| SC-18 | 用真实主程序完成选基准→至少三个条件情景→批量试算→独立检查→KPI下钻→选定/放弃→保存重开/导出；失败、未知及未验如实列明，原型或静态检查不能替代。 |

独立设计算例：8/10=80%；1/4=25%；2×120=240元；同一显示网格内08:07—08:24仍为17分钟。原型的10条需求和固定效果是内置仿真，实际完整肉食品输入可以产生不同合法排程，验收不要求唯一排序或强制80%改善为90%。
