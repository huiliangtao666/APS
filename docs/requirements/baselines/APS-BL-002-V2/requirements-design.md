## 1 文档目的、版本与阅读说明

本说明书由《APS需求分析与设计说明书_v0.3》完整修订而成，汇集截至2026年11月4日本次资料快照的原基线、20项受控CR、143个GitHub Issue及已采集的1094条评论，并纳入当前会话已明确的业务与UI要求。适用于业务设计、开发自测、需求交接及后续UAT准备。

| 版本 | 用途及边界 |

### 1.1 采纳和冲突处理

- 同一业务问题，以有明确来源的后续用户裁决/PM原卡批准范围覆盖旧描述，保留替代关系。咨询答复、候选设计、产品自测、QA/UAT和发布分别标识。
- CR的effective、授权文字、实现状态是不同维度。effective=false但已有明确实施授权的项，仍收录其已授权目标；不据此称产品已生效，也不反向恢复“等待方向批准”。
- 旧Issue关闭可能仅表示咨询、源码、自测或限定阶段完成，不扩写为整个FR/CR或全部用户UAT通过。运行预算、作者分工、某次数据版本不是永久业务参数。
- 引用第一份业务Excel与第二份配置Excel时，配置冲突/歧义以第二份P为准；用户后续确认的生产分钟规则覆盖原“生产按整数天”限制。

### 1.2 配套资料

配套《V2追溯与字典》含基线映射、CR全表、143项Issue采纳记录、1094条评论的来源审阅索引、181项参数目录和实际字段字典。正文与附件来自同一内容模型；附件是派生阅读资料，GitHub Project2仍为唯一实施主账。

## 2 业务目标、范围与系统边界

面向肉食品生产，以需求交期、BOM、批次库存/在途、工艺路线、设备/工装/人员/空间及日历为输入，生成可解释、可核验、可保存的生产计划。先识别缺项，再计算和解释未排/迟交，保护已执行事实，支持条件试算和受控重排。

| 范围层次 | V2目标 | 边界 |
| --- | --- | --- |
| 核心生产 | 单线排程、四类业务数据、统一配置、分钟生产、五类查询和六类结果视图。 | 必要约束只有在已支持且资料完整时才能启用；不可为得到结果自动关闭。 |
| 已授权新增 | 只读主计划报表、紧急插单、基础/CP-SAT选择、独立每日模拟器及读取性能优化。 | 按各CR实际批准范围实施，不把源码存在当已可运行。 |
| 多线与专题 | 多线产品适用和共享资源；隔离预测/复杂工艺/其他资源专题。 | 不能由一般开发授权推导预测冲减、自动补库、新权重或任意返工分支公式。 |
| 真实系统 | 保留数据字典、来源、版本和交换适配边界。 | 模拟采购/模拟质量不等于真实下单、MES执行、QA放行或真实ERP接入。 |

计划、任务、实际执行、质量放行与客户交付分开。新建运行不覆盖已保存方案；参数维护不改变旧run。多解问题按约束、覆盖与数量守恒验收，不强制两种求解器或不同实现给出同一任务排序。

## 3 业务用户、权限与协作责任

| 角色 | 业务动作 | 边界 |
| --- | --- | --- |
| 计划员 | 导入和维护获准模拟数据、配置本次约束、计算、核对、复制试算及提交计划。 | 不得绕过引用保护或将未检查方案当可执行计划。 |
| 计划主管 | 维护获准规则、查看缺口、按既有确认策略确认/退回及归档。 | 部分未排、自审规则按有效策略；共享免登录环境不冒充独立实名审批。 |
| 查询用户 | 查看授权数据、图表、明细和允许的导出。 | 不能维护/计算/确认；不因UI隐藏就放松后台权限。 |

手填“操作原因”及重复共享操作区按Issue #78移除，系统保留自动操作标记和必要审计信息；不能把旧界面要求填写原因作为当前生成或导入的必填前提。正式身份能力与隔离UAT入口分别判断，沿R2.1裁决不将正式Portal账号作为全部业务UAT的默认前置。

依据：[#78](https://github.com/huiliangtao666/APS/issues/78)、CR-R21-UAT02-20261031

Design负责业务需求、原型、规则与场景；PM维护正式CR和唯一原卡并调度。当前新增CR按用户最新“不要多agent互相依赖”要求，工程owner整包开发、自测、范围内修复及交付，不人为拆成轮流等待的微任务。历史Test证据保留；需要独立QA/UAT时由PM按适用阶段调度，QA主责、用户配合；不把独立QA或发布泛化为每张FR关闭门槛。

依据：[#67](https://github.com/huiliangtao666/APS/issues/67)、[#140](https://github.com/huiliangtao666/APS/issues/140)、[#141](https://github.com/huiliangtao666/APS/issues/141)、[#146](https://github.com/huiliangtao666/APS/issues/146)

## 4 关键业务语义、时间与状态

| 概念 | 统一定义 |
| --- | --- |
| 数据集与版本 | 业务数据实例、业务版本vN、配置基线P1/P2、在线配置修订和冻结run各有身份；v4不是数据集类别，也不是永久业务版本。 |
| 数据层 | B业务主/业务输入；P第二份配置；EDIT在线维护；trial本次试算覆盖。仅语义、对象、单位、scope及有效期一致时比较覆盖。 |
| 计划与执行 | 已排是找到计划安排，不是已开始/已完成；工序完成不是质量合格入库，也不是客户签收。 |
| 供给 | 实物批次、已确认在途、期初在制、制造计划、未下达建议独立归类，同一来源只计一次。 |
| 问题 | 最终未排、明确规则冲突、预计风险、计算过程记录与未知依据分开；候选撤销不自动等于最终业务错误。 |
| 未知 | 未提供/未计算/未覆盖/不适用/真实0分别表达；不补0、无限、已完成或合格。 |

### 4.1 时间、单位和边界

生产时间按整数分钟计算与保存，详细甘特按30分钟刻度显示；08:07—08:24仍为17分钟。需求、库存、补料按日，关联生产/放行/投料详情到分钟。显示真实日历日期，时长注明单位；当前样例日0为2026.10.31、默认查询11.01—11.14，11月无31日。

区间采用[开始,结束)，同一时点结束与下一项开始不重叠。dataset/run分别保存原点、时区、精度；开始日期变化不平移原始日历、停机或供给。日业务进入分钟排程采用明确到货、放行、交付截止及失效时点，缺失不得猜00:00可用。

### 4.2 关键状态

| 对象 | 状态及要求 |
| --- | --- |
| 导入 | 已选文件→上传/解析→预览待确认→确认接纳或失败/待对账；预览不是导入成功。 |
| 计算 | 待检查→就绪→排队→计算中→完成/部分未排/未找到解/失败/取消。数据或条件变化使旧就绪凭据失效。 |
| 计划 | 草稿/试算→提交→确认或退回→归档；修改影响结果后重核。只有适用已排部分允许被确认，不忽略剩余清单。 |
| 执行 | 未开始、已开始、部分完成、暂停、已完成；累计事实不能倒退、越量或通过恢复旧方案抹除。 |
| 质量 | 按显式配置区分待检、冻结、不合格、合格/可用；计划/预计放行与实际模拟声明分别标识。 |

## 5 核心业务流程与异常闭环

| 步骤 | 主要页面及操作 | 完成结果/下一步 |
| --- | --- | --- |
| A1 数据准备 | 业务Excel与参数Excel分别上传、预览、整批确认；必要映射显式维护。 | 获准版本和配置基线；失败保留原数据，未知提交先查回执。 |
| A2 就绪补缺 | 按本次需求/日期及真实依赖闭包检查，问题定位到表/行/字段。 | 已支持约束的数据完整；未支持项不假装已检查。 |
| A3 本次配置 | 选择范围/观察时刻、采用参数scope、规则、求解器和有效预算。 | 参数/条件变化使旧凭据失效，重新检查。 |
| A4 计算 | 创建新run冻结输入，显示真实阶段、取消与停止原因。 | 可行/部分/未找到解/失败分别进入核对，不能把计算中截图当完成。 |
| A5 结果核对 | 指标→同口径问题弹窗→六视图→来源/节点公式；必要独立检查。 | 未排、迟交和条件供给清楚；合法调整/锁定需再检。 |
| A6 保存导出 | 保存、复制比较、采用/放弃、按既有确认条件提交/退回/归档。 | 重开原run保持指纹；完整筛选导出与页面一致。 |
| 异常重排 | 更新事件时点累计事实→保护已开始/完成→重排净剩余→比较影响。 | 插单批次及新run可追；不抹去执行和不覆盖原确认计划。 |
| 每日模拟 | 独立场景日推进→完整日结/检查点；适配门通过后再与主程序循环。 | A、B里程碑分开，未启联动不能写当前主程序。 |

各步骤允许返回查询/维护，保留当前选择、范围及必要定位。维护保存后刷新当前查询身份、重新就绪检查；不以被隐藏的筛选、旧版本缓存或旧结果蒙混当前条件。

依据：[#71](https://github.com/huiliangtao666/APS/issues/71)、[#96](https://github.com/huiliangtao666/APS/issues/96)、[#108](https://github.com/huiliangtao666/APS/issues/108)

## 6 功能需求及相互关系（完整修订）

以下逐项为V2当前业务要求；FR编号沿原基线。原始条文、原卡URL、原阶段与适用AC在追溯附件保留。新增/修订内容的依据见相关CR及Issue，能力和授权边界另见第12、15章，不将本章编制当实施完成。

### 6.1 基础数据与资源配置

#### FR-001 产线、工位及资源归属

维护工厂、产线、工位和资源归属，单线核心模式与已授权多线模式明确区分。同线可有多道工序、并行设备；不把一台机器等同一条产线。未启用多线时，跨线引用应提示并阻止计算。

验收映射：AC-01、AC-02。变更来源：CR-UIUX-FLOW-20261031。

#### FR-002 产品、物料与单位配置

维护成品、半成品、原辅料、包装材料及来源/基础单位，区分采购、制造、包装等业务来源；保留支/袋/箱/千克等明确换算及净重。编号用字母数字，仿真名称具行业辨识度。数量比较和汇总只能在同物料、可证明的量纲转换下进行。

验收映射：AC-02、AC-08、AC-09。变更来源：CR-DEC04-05-06-20261029；CR-SCHED-CONFIG-20261031；CR-UIUX-FLOW-20261031。

#### FR-003 BOM、收率与包装用量配置

维护有生效版本的多层BOM、投入/产出基准、投料位置、标准收率及包材用量，支持逐物料生产损耗与受控换算/最小包装单位取整。标准投入基准和已含收率的Excel产出基准分别标profile，不重复扣收率/损失；实际投料日期重核有效配方。三类损耗、计算及未决边界见第7章。

验收映射：AC-08、AC-09、AC-15、AC-32。变更来源：CR-DEC04-05-06-20261029；CR-SCHED-CONFIG-20261031；CR-UIUX-FLOW-20261031；CR-BOM-LOSS-20261031；CR-PACK-BATCH-20261031。

#### FR-004 工序与工艺路线配置

维护成品及制造半成品的显式工艺路线、前后工序、设备组、工时/等待、程序、投料点和资源参与关系。每个制造物料须有可采用路线，不按名称猜映射。准备、运行两阶段各可固定历时或按量；复杂分支/汇合/返工与配方自动选择按专题范围另行明确，不由本条自动开启。

验收映射：AC-02、AC-04、AC-13、AC-14、AC-15。变更来源：CR-DEC04-05-06-20261029；CR-SCHED-CONFIG-20261031；CR-UIUX-FLOW-20261031；CR-PACK-BATCH-20261031。

#### FR-005 机器能力及适用范围

维护设备组、适用工序、独占/容量共享、可用数量、单批上限及共享总容量；两种容量分开。固定程序历时不随未满载缩短。共享模式任意时点各批占用含WIP不超容量，独占模式不重叠；非法或未支持的组合须明确阻塞。

验收映射：AC-04、AC-09、AC-13、AC-15。变更来源：CR-DEC04-05-06-20261029；CR-SCHED-CONFIG-20261031；CR-UIUX-FLOW-20261031；CR-PACK-BATCH-20261031。

#### FR-006 模具及工装配置

维护实体工装、类型、适用任务、套数、可用窗口、提前取得/后延归还及共享策略。校验完整占用区间，不能仅看加工主体；相同实体不能因不同组名重复计容量。mock取得/归还/释放账明确仿真及谱系，不当真实工装实账。

验收映射：AC-06、AC-15。变更来源：CR-DEC02-03-20261029；CR-SCHED-CONFIG-20261031；CR-UIUX-FLOW-20261031。

#### FR-007 人员数量与技能配置

维护人员组与唯一物理池、人数、技能、班次、任务参与阶段/窗口、提前/后延和释放；有向技能替代必须显式配置。窗口外占用即使图形未画也须提示和检查。检查顺序可配置，但最终完整区间均须满足可用性/容量；不能复制人员池放大人数。

验收映射：AC-07、AC-15。变更来源：CR-DEC02-03-20261029；CR-SCHED-CONFIG-20261031；CR-UIUX-FLOW-20261031。

#### FR-008 工作日历与停机配置

维护工厂日历、班次、资源继承与停机例外，生产窗口保留分钟。区分计划停机与非计划事件及其可知时刻，未来未知故障不得提前扣能力；重叠停机按并集。连续工序按配置判断跨班/中断，不能把离散班次简单拼成连续可用时间。

验收映射：AC-05、AC-07、AC-14、AC-15。变更来源：CR-R21-UAT02-20261031；CR-SCHED-CONFIG-20261031；CR-UIUX-FLOW-20261031。

### 6.2 需求、供给与模拟执行

#### FR-009 订单与需求数据

维护需求身份、成品、数量/单位、客户/区域/等级、要求到货与工厂发运日、优先顺序、允许拆分和适用产线；数量/交期变化留历史。取消或减少需求不抹去已执行事实。既有日需求、紧急增量和隔离预测分开，常规肉食品场景不引入促销或每日预测差额。

验收映射：AC-01、AC-02、AC-12、AC-20。变更来源：CR-SCHED-CONFIG-20261031；CR-UIUX-FLOW-20261031。

## 7 业务规则、数量公式与配置参数

### 7.1 参数优先级、版本与维护

- 第一份B提供业务/主数据及基础值；第二份P的定义/范围/适用有效值优先。在线EDIT及显式trial沿既有受控覆盖；只在同对象、字段语义、量纲、profile、scope和有效区间下选当前值，不因同名直接覆盖。
- 明确待补/暂停采用的P项不得偷偷退回B；缺值、显式0、清空、继承及未启用不相同。物料统一损耗初始0%是已确认局部默认，不推导其他参数可默认0。
- 正式参数文件形成P1/P2等基线；在线参数维护保留配置修订和修改前后日志，不增加业务数据版本。试算覆盖与共享采用明确区分，新参数导入与旧在线覆盖冲突须有选择/对比及版本保护。
- 同CP/对象/字段/有效日主表只展示一项当前值，按CP升序。全局清单、对象矩阵和工厂日期网格分工；未维护/只读/候选显示状态，历史值进日志。

### 7.2 BOM、收率与损耗

先声明数量profile。标准投入配方中qᵢ为同基准、统一千克原料定额，lᵢ为该物料生产损耗：Y=Σ[qᵢ×(1−lᵢ)]；生产收率r=Y/Σqᵢ；目标合格产出Q所需物料投入=qᵢ×Q/Y。不可简单平均损耗或再乘旧固定产品总收率。原料/生产/运输损耗分开，原料及运输上游特殊应用公式未明确的不擅自新增。

已批准说明算例：650/150/150/50千克，生产损耗2%/4%/10%/0%，保留产出637+144+135+50=966千克，派生收率96.6%。这些数值仅算例；每物料可覆盖，未覆盖继承统一值，显式0与继承不同。

依据：CR-BOM-LOSS-20261031、[#38](https://github.com/huiliangtao666/APS/issues/38)、[#39](https://github.com/huiliangtao666/APS/issues/39)

已含收率的Excel产出基准BOM：父项基准产出Qᵦ，子项定额gᵢ，则目标Q的该子项毛用量=gᵢ×Q/Qᵦ，不再除一次相同收率。单位换算、包装最小单位及数值精度各自有证据；同批次/同来源不因展开BOM、重复映射或多视图再扣料。

### 7.3 包装、批量与补货

包装数量=有效工时×已明确速率；两项可配置，反推工时须速率>0，明确速率单位及是否已含效率，不硬编码50分钟，也不再加未要求效率。包材按最小包装单位u向上取整：用量=ceil(精确需求/u)×u，保留精确量、执行量及差额；不能反向自动超产填满设备。

不足一批允许按批准策略生产及兼容合并，但仍受单批上限、共享总容量、程序/配方兼容、等待/下游空间及数量守恒约束。组批资源只代表共同加工，不丢订单/生产批身份。

依据：CR-PACK-BATCH-20261031、[#39](https://github.com/huiliangtao666/APS/issues/39)

采购净需求、库存、安全目标和现有供给须同一物料/单位/时点/占用范围；有正净补量n、MOQ m、订货倍数k>0时，建议量按ceil(max(n,m)/k)×k处理，n=0不因MOQ强造采购。采购/检验提前期、日历及可用时点共同决定最早可用，迟到风险如实保留；建议不自动变已下单供给。

### 7.4 准备—运行两阶段与容量共享

用户确认采用容量共享；每个路线工序仅分准备、运行两阶段，阶段计算方式各选固定历时或按量，默认固定历时。固定阶段直接采用时长；按量阶段T=ceil(Q/Q基准×T基准)，向上取整数分钟。准备可显式0，运行必须>0，空值不当0；小时输入明确换算为分钟。

每批准备→运行→释放，每个拆批各算准备。两阶段均按规定装载节点的该批数量占共享容量，任意t有Σ占用量(t)≤共享总容量，WIP及必要保留也在内。单批上限与共享总容量分开；同一清洗若已由换型关系计入，不再在准备重复计。既有独占历史run保留原语义，不靠改一个上限值自动切模型。

依据：[#114](https://github.com/huiliangtao666/APS/issues/114)、[#115](https://github.com/huiliangtao666/APS/issues/115)、[#116](https://github.com/huiliangtao666/APS/issues/116)、[#117](https://github.com/huiliangtao666/APS/issues/117)、[#118](https://github.com/huiliangtao666/APS/issues/118)

物料本级生产提前期、采购/检验及本级补给提前期分开说明单位。沿有效BOM累计提前期Aᵢ=Lᵢ+max(A子项)，没有制造子件时Aᵢ=Lᵢ；有并列关键路径应说明。此图是静态关键路径参考，不是有限资源下真实开工承诺。查询有效日与实际投料日可不同，应标明，不能混用失效BOM或旧参数。

| 约束 | 边界、合法组合、规则、前提和要求。 | 不支持或待确认的约束明示。 |

三层连线：步骤→实体标题；底座内→具体字段；数据源→明确属性端口。源映射与五类业务关系分开，可正反向追溯；六列全名保留，列间留足连线通道。V7已确认80px列间距、2460px完整画布及适宽/100%阅读是独立HTML展示值，不成为主应用所有页面宽度。

> Ontology系列是独立设计/说明HTML；不代表已部署真实知识库、OWL推理器、新求解约束或生产交易闭环。发现的BOM有效期、WIP来源缺项等仍按真实接口/业务状态处理，不能靠图中有一条线宣称已实现。

### 9.3 紧急插单（#67）

在选定生产计划的工作台提供“插单提交”和“插单排程”。提交可接仅含“每日需求”页或原整本xlsx，但只消费需求页；沿原第1行综述、第2行中文表头及第3行起数据、17列合同，不要求给Excel加系统批次/时刻列。预览对客户/成品、数量换算、日期、映射、重复编号等逐项校验，整批生效且幂等，不改其他库存/配置。

生效后按基准计划真实执行、当前采用参数及有效规则，对全部净剩余工作优先安排插单，其他未执行任务可调整；已开始/已完成、不可挪用供给、锁定和保护约束仍有效。不能把插单简单拼接在末尾、仅算插单后称重排，或抹去常规需求以制造可行解。失败保留原方案，成功生成独立新run及谱系，不自动采用或发布。

| 影响页签 | 必须展示 |
| --- | --- |
| 插单结果 | 每条插单可行/未排、数量、预计发运/到货、条件/原因。 |
| 原订单影响 | 原需求数量、前后发运/到货/未排、变化分类和新增迟交；“全部”包括未受影响原需求。 |
| 工序与资源变化 | 稳定任务/生产批谱系、前后时间/资源/占用、直接和连锁原因。 |
| 未排与原因 | 原单与插单分别列未排及缺失条件，按合法单位汇总。 |

来源包括基准/新计划、插单批次/需求、输入/P/执行事实、BOM/路线、文件页签行及求解器。若同时变化事实或参数，应分列原因，不能把全部差异都归因插单。页签、明细、全量筛选导出同一版本/单位；关联甘特可定位。

### 9.4 基础求解器与CP-SAT（#141）

新建生产计划默认当前基础求解器，可在A3/生成页单选CP-SAT；本次步骤往返保留明确选择，不能被上次浏览器缓存暗改默认。CP-SAT必须真实参与本次排程，后台验证请求选择和实际执行一致；旧调用未传选择沿基础，显式非法值拒绝。

两引擎使用同一冻结数据/规则、分钟粒度、必要资源物料约束与独立检查。必要启用项未支持应精确阻塞，不能静默关闭、软化或回退基础。业务小数按明确精度等价转换，不截断或补量。无明确优化目标时做可行性求解，不隐藏最短总工期/成本权重；不能可选零排却称成功。

| 原始状态 | 业务解释 |
| --- | --- |
| OPTIMAL | 有可行结果；仅在明确优化目标和模型范围内称已证明最优。无目标称找到可行解。 |
| FEASIBLE | 已找到可行解，未证明最优；按实际覆盖和独立检查处理。 |
| INFEASIBLE | 本次模型/范围/窗口已被证明不可行；不扩为企业业务永远无解。 |
| UNKNOWN | 规定条件内未取得可用解/未证明不可行，不等于无解。 |
| MODEL_INVALID | 模型校验失败，与业务缺料/不可行分别定位。 |

最大求解时长以秒计，是计算控制而非生产精度；继承有效运行预算，预处理/交付/检查也占总保护预算。取消沿真实终态、回收槽位，不假采用候选。记录请求/实际引擎、版本、时长、目标/覆盖、停止原因及检查；保存重开、历史未知、原生导出和比较一贯。真实CP依赖/预算未具备不能用模拟引擎冒充。

依据：CR-SOLVER-CHOICE-20261103、[#141](https://github.com/huiliangtao666/APS/issues/141)

### 9.5 每日数据模拟器（#146）

阶段A独立场景/分支、基线副本、模拟时钟/脚本、规则/随机版本、日推进、检查点/恢复新分支、日间比较及导出。按天推进，生产和资源事件保留分钟；没有计划只能推进已声明非生产脚本，不凭空生成生产任务。基准无随机，启用随机需种子、版本、概率/范围并保存物化事件。

需求生效、部分采购到货、待检/放行、耗料、在制/完工、工装归还、停机、显式恢复、到期/报废、发运/签收分别发生并对账。单日失败不移成功检查点，不暴露半日正式状态；相同身份/内容重复不再扣料或收货，异内容冲突；跨重启持久去重。历史修正新分支，未知回执先对账。

日结处理[D日00:00，D+1日00:00)，次日零点事件归新日；若零点联动排程，先应用该时点已知事件形成开工快照。物理发生、信息可知、生效及归账业务日分开；脚本作者可见的未来故障不提前泄露给求解器。

物理库存=期初+实际收货+实际制造入库−投料−发运−实际报废等；放行不再加实物，到期失效与实际出库不二扣。累计耗料30→80只新增50。采购订购=累计已收+明确取消+净未收；制造/签收/发运分别核销。故障修复不自动等于允许继续加工或质量合格。

独立A调试及适用验证通过、选定范围接口缺项解除后，PM才组织B受控联动：已知事实→完整版本接纳/对账→主程序就绪/求解→按既有规则选定新计划→下一时段。A通过不将整CR或B标Done，初始不写当前主程序/原Excel、不调主求解、不启动平台定时任务。

须适配的重点：Excel在制非完整累计执行；CSV两套时间原点/非负限制；部分收货/履约；扣耗前账面与累计耗料；质量/恢复；一天多时点事件事务；跨重启回执；迟报冲销。现有本地mock与内存Map不证明真实联动或恰好一次。缺项明示，独立新增字段不塞入原接口白名单。

依据：CR-DAILY-DATA-SIMULATOR-20261104、[#146](https://github.com/huiliangtao666/APS/issues/146)

### 10.3 通用筛选、栏位与分页

- 选项多的筛选框内搜索并多选，初始和重置实际全选当前版本范围内全量候选；不是仅第一页打勾。搜索保留隐藏已选，同字段并集、跨字段交集；清空产生空结果，恢复全选有明确动作。
- 同一时刻只展开一个下拉；打开另一项、点击外部或Esc收起，选择不丢。弹层不撑高结果区、不被滚动容器裁掉，查询/重置位于操作带固定可达位置。
- 每个表和图形视图都有独立“显示栏位”，表头和数据同步隐藏，偏好分别记忆并兼容旧组合栏位。必要标识可固定；隐藏不删数据或日期图。
- 默认每页100，可选200/500；先全量筛选、稳定排序、计数/汇总后分页，条件变更回第一页。完整筛选导出不是当前一页；候选分页也不能把全选缩成一页。
- 有物料筛选的适用页支持“根据BOM显示”；开启按有效版本/日向下递归、多根并集与共享子件展示去重，关闭只看所选层，不按编码猜关系，不改变需求/分配。
- 移除的或不适用的筛选不得留在缓存中暗中生效；不同子页切换要显示真实当前条件，不共享一套错误筛选。

### 11.1 数据读取与缓存专项

CR-DATA-READ-PERFORMANCE-20261104要求在相同输入和真实IO下比较优化前后冷读/热读；以中位读取时长约50%及以上改善为工程目标，结果连同文件规模、环境、次数和语义一致性报告。不能把纯内存mock或跳过读取当成真实IO加速证据。

依据：[#147](https://github.com/huiliangtao666/APS/issues/147)
