# Issue3 P08/P09 人员岗位身份

范围：v0.3 + CR-DEC02-03-20261029；FR007/022；delivery dlv_8e493d57-3f86-48a9-85a3-b7dcb9a53968。不是产品缺陷返修轮次。

表12新增可选中文字段“人员岗位编号”，1–64字符，不含首尾空白或控制字符。编号由维护者显式填写，不提供业务默认值。身份作用域为订单/工序及生产批；不同岗位在重叠区间需求相加，同岗位各阶段按每一时间片的最大人数计算。无重叠时按实际窗口扣算；不承诺跨窗口具体自然人员身份。相同岗位的候选组集合、技能、班次须一致，冲突配置原子拒绝。窗口人数可不同。人员阶段继续区分同岗位的多行窗口。

兼容：旧记录字段缺失或空串继续使用既有角色合并规则，旧CSV表头允许省略该列；不自动为旧记录分配岗位。新记录唯一键包含岗位和阶段，不同岗位可使用相同阶段。Worker需求键仅在显式编号时追加岗位身份，旧需求键原字节不变。新账本记录postId并在reason展示；独立检查器从冻结输入单独重建编号和时间片，拒绝缺岗位、重复挪用或伪造需求键及标签。旧无demandKey账本的兼容回退仅限旧未编号单组记录。

冻结与保护：沿用原有执行核对守卫：存在已接纳执行事实时，dependencies表变更会以409 execution_reconciliation_required拒绝，须先走既有核对流程；不绕过原始事实保护。配置修改仅影响新运行；不迁移既有plans/runs/confirmations或执行事实。新增字段进入原有输入hash、冻结快照、权限审计、CSV和差异比较。非法字段、合同冲突、越权或陈旧版本提交在存储写入前拒绝。

回退：在保留此版本读取能力的环境中显式清空岗位字段会恢复旧合并语义，属于需审查的业务变更。不要把已编号配置交给旧程序运行（旧程序不能理解独立岗位），回滚产品前先恢复完整的原版本配置和匹配数据库备份；保留现有历史原件，不静默删字段。

验证脚本：qa/p08.test.mjs、qa/p08-browser.mjs、qa/p08-fixture.mjs。隔离应用容器运行，复用qa/fr027-fixture.mjs合成身份、真实角色中间件和React/Express/异步Worker/冻结复核。合成身份验证不等于平台SSO或业务UAT。根目录报告及证据由APS-PM通过Files API取得，独立Test由PM调度。
