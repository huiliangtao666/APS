Delivered behavior
Reuses the existing constructive scheduler, run freezer, actual Worker, server authority, rule configuration and UI. No second scheduling engine or new app/identity/backend channel. MATERIAL is now an explicitly supported opt-in rule; the existing seed leaves it disabled. Enable it with the complete v0.3-shaped parameters, for example:
{"允许预计供给":false,"可用状态":["合格"],"预计状态":["预计可用"],"不可用状态":["待检","冻结","不合格"]}
All four parameters are required. Status lists must be nonempty, unique, trimmed and mutually disjoint. Unknown parameters, narrowed scope, unsupported rule enablement and missing BOM remain rejected. MATERIAL status lists govern allocation; INVENTORY's separately frozen status rule continues to govern the availability query. This distinction is stated on screen and in the rule snapshot; changing one does not silently rewrite the other.
For every supported order and operation, choose the latest BOM effective on the factory feed date; reject multiple versions on that same latest date instead of choosing by arbitrary version text. Resolve material IDs, product, operation, unit and version from validated canonical records. Demand includes each BOM row at its own operation feed point. Explicit material dependencies must have a corresponding BOM row; dependency quantity is never added to BOM demand a second time.
Demand uses order remaining quantity, converts only declared kg/支/袋 via product net weight and pieces per bag, and retains the exact formula, quantity numerator/denominator, remaining kg, source version/effective date and feed time. Completed-quantity equality produces no new tasks in MATERIAL execution. Full order completion and WIP protection are separate R5 acceptance gaps.
At the actual candidate start AFTER predecessor, machine and calendar shifts, check quantity net of existing occupancy, prior allocations in this plan, declared quality status, availability time and expiry. Allocate eligible lots by expiry, then deterministic stock-before-conditional and lot-ID ties. Stock and expected supply are separate source keys; a stock/expected duplicate batch ID blocks allocation to avoid double counting a receipt as both sources. No substitution material or invented receipt.
A preview never reserves stock. Only a scheduled operation passing the existing horizon/personnel checks commits its complete preview. Shortage previews cannot commit, repeated commit is idempotent and a stale preview cannot overwrite later allocations. All material rows for a failed operation roll back together; successor demand is retained as a candidate with its predecessor-block reason, without consuming stock. Already scheduled predecessor material stays allocated when a later operation cannot run. This is a partial plan, not a globally feasible-order certificate.
If not covered now, search subsequent imported stock/expected ready instants and recheck all resource/material conditions; otherwise leave the operation and its dependent successor unscheduled. Unscheduled does not prove global infeasibility. Retain lot splits, quantities, remaining capacity, shortages, source status, expiry, availability and conditional explanations. Procurement/preparation are suggestions only.
Allocation and deduction are PLAN-SCOPED projections, not physical inventory movements or global reservations across alternative scenarios. Re-running from the same immutable input produces equivalent allocations and does not decrement input inventory again. Adopting or executing a plan does not write real consumption back in this stage.

Unit / conversion / rounding trace and conservative boundaries
v0.3 AC08 explicitly gives480kg qualified output /0.96 total yield =500kg input, with650/150/150/50 per1000kg ->325/75/75/25kg. Integrated FR003 fields map canonical CSV计量基准/定额/投料工序 to用量基准/配置用量/投料工序编号; product总收率 remains the sole total only-loss yield. Supported raw basis is exactly每1000kg投入 in kg, with complete raw-row quota sum1000. No automatic normalization or ratio guessing. Nonzero raw damage or nonempty free-text loss/addition notes block; the program does not interpret prose or apply a second loss multiplier.
v0.3 AC09 and7.1 specify product单支净重kg and每袋支数, and领用量中损坏比例. The existing integrated BOM schema lacked a machine-readable damage field: added optional损坏比例, but calculation REQUIRES it explicitly on packaging rows. Supported packaging basis is每袋, output unit个, configured per-bag quota, using ceil(required bags * quota / (1-loss)). This yields1213 and809 at480kg,0.04/0.06kg per piece,10pieces/bag and0.01loss. No default1%, no extra1% approximation. Raw units are not rounded. Packaging intermediate pieces/bags must be integers; the baseline does not settle partial-piece/bag intermediate rounding, so those cases remain unscheduled. Final packaging ceiling comes directly from7.1.
Order schema adds optional已完成合格数量, in the SAME数量单位 as合格需求. Blank means no declared completed quantity, preserving existing new-order behavior. Remaining =需求−已完成合格数量; validation rejects negative, nonfinite and over-completion. This is an explicit simulation input for cumulative qualified completion, not an inferred MES fact, actual material debit, partial WIP or per-operation remaining-work reconciliation. Unreported execution consumption cannot be inferred; R5 remains unsupported.
kg/支/袋 conversion follows the product fields and AC09. 箱, arbitrary material-unit conversions, standalone per-operation yield/loss/addition models and arbitrary basis strings remain blocked. No invented box-size/default yield, no duplicate total-recipe additions. Fixed durations remain from FR019; AC09 speed-derived100/80minutes is NOT implemented or claimed.
Decimal quantity decisions use reduced BigInt rational arithmetic with no epsilon. Exact numerator/denominator strings persist alongside numeric display/export values. An exact0.1kg shortage cannot disappear in display tolerance. Stored display values are never fed back into allocation calculations. Existing minute-axis numeric/fractional timing behavior remains.
Time origin remains FR011/018's2026-11-02T08:00:00+08:00; start selection does not rebase it. v0.3 factory timezone isAsia/Shanghai (+08). Both inventory-query expiry and allocation/BOM dates now use this factory day, including local midnight; expiry dates retain the existing inclusive-day meaning, with next-day00:00 excluded. This fixes an inspected UTC-day mismatch rather than inventing a new timezone. Existing stock readiness schema still accepts Date.parse timestamps; explicit-offset supply timestamps retain FR011 validation. Arbitrary plant timezones and minute-expiry source CSV conversion are not silently inferred.

Expected supply and modes
Expected source rows retain FR011 delay history, effective arrival and effective available instants. Under MATERIAL, they are candidates only when允许预计供给=true AND explicitly referenced by订单/工序/供给. Allocation is capped by the reference quantity, aggregate source capacity and prior plan consumption, and only after effective availability (which validated data keeps at/after arrival).
Existing FR011 supply rows lack status/expiry. Added optional质量状态/有效期 for backwards-compatible storage; MATERIAL requires a qualifying expected status and expiry before using that row. Missing data yields shortage, not an invented qualification. Conditional does not mean real quality approval: each allocated expected lot remains contingent on arrival, quality and expiry being as simulated; there is no goods receipt confirmation or purchase order. SupplyConditions uses quantities actually allocated, not the maximum reference allowance. Imported source/quantity/delay records remain unchanged.
When MATERIAL is disabled or not yet effective, supported mode retains FR019 calendar/personnel/explicit-supply behavior and explicitly labels material unchecked. With active MATERIAL it adds only the described BOM/allocation scope; all unimplemented constraints remain unchecked. Explicit minimal-r1 still performs only continuous-machine/precedence scheduling, does not calculate/reserve materials or wait for supply, records material unchecked and marks MATERIAL inactive for that execution. It never becomes an automatic fallback. Stored rule configuration is still validated even when a minimal execution omits that check.
