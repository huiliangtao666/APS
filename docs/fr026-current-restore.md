# FR026 当前事实恢复

授权：APS-PM delivery `dlv_3e79eeae-e281-4ebe-876d-53d7f03dad92`，v0.3 FR026 / AC03、12、20、32 本卡责任。不是 Issue14 返修轮次；Issue14 保持 closed。基于 e0be9b6dfbf9be7ce404edc1b80d8c50858ed3dc，保留 P08/P09 人员岗位与 CSV 改动。

恢复复用旧方案明确保存的订单选择、时间范围、优先级、规则选择和位置锁定，以**当前全部输入**（包括库存、工艺/BOM、资源、执行事实、累计耗料及事件）计算新方案。不会恢复旧输入表、旧库存或旧确认状态。规则选择失效、订单失效或来源不完整时拒绝，不推定业务默认值。新方案是可经现有复核/提交/主管确认流程采用的草稿，旧确认继续保留；不自动替换确认计划。

API：计划员或主管带操作原因及当前 revision 调用 `POST /plans/:id/restore/check`。真实 Worker 计算和独立复核后返回临时预检 ID、五维比较、当前事实版本与确认引用。预检无持久化写入。检查采用当前启用规则，来源运行可重放且确认历史摘要一致；缺已开始工序的物料累计耗料、未知事实口径、资源/物料冲突或未排结果均拒绝。已开始物料不推定为零耗料。

`POST /plans/:id/restore` 带 revision 和 previewId 保存。预检 ID 绑定用户、来源方案、整个业务存储摘要，15 分钟有效，重启失效；输入、事实、确认或其他业务记录变化均要求重新预检。同一预检只能保存一次。保存前复查，保存时输入/原方案/确认/原运行不变，仅追加新运行、方案、来源及审计；单进程内通过临时文件加原子 rename 一次提交。成功后可刷新、复核、复制、比较或放弃独立试算。

仅支持现有内部模拟语义。真实 Gateway 签名、真实客户事实、完整业务保护、QA UAT、发布与 main 合并未执行。允许有明确原因的部分计算是既有确认能力，但本恢复入口不会自动接纳未排或冲突结果。新草稿仍须用户走已有确认流程；恢复不构成确认业务参数或 QA 放行。

自测入口：`FR026_REPO=<绝对检出目录> FR026_OUT=<新证据目录> bash qa/fr026-restore-docker.sh`。依赖现有隔离测试镜像 `aps-fr038-qa-runtime:latest`，容器内安装浏览器；前台使用 QA-only synthetic actor，生产入口不接入该 seam。用真实 Express、React、Worker 和原子 JSON 持久化验证，不构成 Gateway 验证。生产应用数据与已绑定入口均未修改，无迁移；回退代码不删除追加的历史。
