RAW01 — untouched multiline field contents silently rewritten
Location: src/lib/csv-draft.mjs editCsvDraft(), especially prefix/suffix span and inserted.replace(/\n/g,newline); used by CsvBatchPanel textarea onChange.
Trigger: an LF-normalized textarea replacement makes two separated corrections with original mixed newline content between them. A common route is select-all and paste the corrected visible CSV. The function treats the entire first-to-last change span as newly inserted and converts every LF in that span to the first newline style, including unchanged quoted field content.
Reproduce with attached raw01-repro.mjs against pinned source:
1. Start disposable real React/Express membership fixture, calculate seed plan; select six files generated from seed. Machines MIX01 name is "START\rKEEP_CR\nKEEP_LF\r\nKEEP_CRLF"; MIX02 maximum load is "bad". The file has CRLF record separators.
2. Preview. Activate the maximum-load issue by keyboard Enter. Exact physical row6 is selected.
3. Select all in the raw editor; insert corrected visible CSV changing only START→CHANGED and bad→1200. Unmodified KEEP_CR/KEEP_LF/KEEP_CRLF contents remain visually present.
4. Re-preview; it succeeds. The actual outbound raw file contains "CHANGED\r\nKEEP_CR\r\nKEEP_LF\r\nKEEP_CRLF" instead of the required "CHANGED\rKEEP_CR\nKEEP_LF\r\nKEEP_CRLF".
5. Confirm by keyboard Enter. HTTP success and revision1 persist the altered name exactly. Original plan/audit hashes are recorded before/after. Preview itself leaves all persistent bytes unchanged.
Expected: preserve all unchanged raw substrings/newlines while applying the requested corrections, then reparse and commit that exact corrected source. Actual: unrequested quoted field content changes are accepted as input. Impact: silent data mutation during correction, violates the explicit original-text preservation contract; affects genuine workflow, not just a missing test. Suggested severity medium: content corruption is bounded to an editing pattern but persistent and not indicated to the user. Do not claim that every edit corrupts text: no-change/single-local-edit cases passed.
Evidence: independent/multi-edit.json and first screenshot; raw01-repro/report.json, original/expected/actual machine CSV bytes, accepted-corrupted-preview.png, persisted-success.png, persisted-business.json and semantic tree. First reproduction used textarea fill; second used keyboard ControlOrMeta+A followed by insertText and keyboard commit. Both use unmodified pinned product code.
Fix direction: preserve source-to-normalized offsets for separate unchanged spans or apply the actual edit range; do not normalize every newline between the first and last change. Add mixed-newline multi-correction/replace/paste cases. A corrected implementation still needs actual browser re-preview/commit and source-preservation retest; no fix or retest PASS is claimed here.
