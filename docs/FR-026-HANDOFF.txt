Implementation
Server-authoritative POST /plans/:id/copy copies validated immutable original input version, saved tasks, allocations, assessments and conditions into a separately identified draft result and trial. Copy preserves original plan/run/inputVersion/snapshot references, source creation date and source verification as provenance; it never transfers verified or confirmed authority to the new draft. Original input hashes and frozen run hashes must validate; missing or corrupt historical inputs block copying/comparison. Old snapshots are not rebuilt from current data. Client actor/status/provenance/results are ignored.

GET /trials supplies independently stored trial inputs. POST /trials/:id/inputs uses shared schema/reference/business-rule validation, a separate compare-and-swap revision, immutable input versions, and trusted actor/reason/request/time audit with trialId. It cannot alter workspace revision/data or old plan input versions. Trial table edits are excluded from the workspace order-change history display. Repeated identical input replacements remain idempotent. Trial inventory/quality/order quantities are simulations, not execution facts.

POST /runs and /calculate accept a validated trialId and trial revision. They freeze that trial's data and selected conditions rather than live workspace data. The inherited Worker lifecycle/capacity/timeout/failure/cancellation authority and saved reports remain. Every actual recalculation gets its own run/plan identities, input version and execution hash with trial/source references. Copy initially references the original run and explicitly labels copied result provenance; it does not fabricate a new calculation. Exports include trial/source/result-origin references, including copied-not-recalculated results and no-result runs. Input snapshots remain inspectable after later trial/live edits.

POST /trials/:id/discard atomically marks the trial discarded before awaiting active Worker termination; new edits/runs are blocked during shutdown. Active trial runs become cancelled with trial_discarded reason. Original/confirmed plans, current input, earlier saved results and run snapshots remain unchanged. Discard retains trial/history for review. Repeated discard with current revision is idempotent. Discarded trial snapshots cannot be copied, saved or verified as active work. A copied plan is always draft. Real confirmed state exists only in an explicit storage test fixture, not a product confirmation route.

GET /plans/:id/compare/:other compares saved evidence only. It reports task start/end/duration/machine/precedence; all saved machine/personnel/tool/space reservations; full material demand and lot allocations with exact rational quantities, shortage, conditional/committed flags; order required due date, production completion, conditional deliverable time/delay and saved quantities; and per-operation unplanned quantities without summing a route's quantity multiple times. Input table before/after and calculation condition/check-scope differences accompany the comparison. Resource ordering does not create false changes; duplicate material keys retain every record. Unknown/unchecked evidence stays null/unknown. Unchanged order outcomes explicitly state no delivery improvement. Changes require per-order review and do not imply optimization or actual delivery.

TrialPanel provides independent input editing through DataEditor, selected-scope asynchronous calculation using RunPanel, saved result navigation, discard, and before/after comparison with provenance. It initializes from the copied selection, including an absent horizon, and reuses the existing operation reason and permissions. The restore guard displays concrete server blockers. Normal plan/history/input/Gantt interactions remain available. UI tests exercise component events, not authenticated browser acceptance.

Safe restoration
POST /plans/:id/restore checks current workspace revision, rereads current inputs and returns409 restore_blocked with currentRevision/currentInputVersionId, source plan/run/input references and historical-input availability. currentProgressVersion/executionFactsVersion/confirmationReference remain null. Blockers explicitly identify CURRENT_PROGRESS_RECHECK_UNAVAILABLE, CONFIRMATION_CONTRACT_UNAVAILABLE and STALE_STOCK_RESTORE_FORBIDDEN. R5 progress/remaining-work/consumption and real confirmation contracts do not exist, so even identical input hashes cannot establish a safe restore. No historical inventory/occupancy or execution facts are written. Existing /inputs and /tables/:table operation=restore routes are also blocked after input validation, closing the old whole-table restoration path. Invalid payloads can return400 and stale revisions409 before the restore gate; none writes state. The previous FR015 success test was updated to require this intentional safer behavior. Ordinary simulated data editing remains available; it does not claim R5 execution protection.

Future restoration must integrate authoritative current progress/consumption versions, protected work and real-confirmed-plan references, recalculate remaining work/material availability, independently recheck all adopted constraints, and commit with current version guards. Do not reinterpret today's null references as proof of no execution and do not enable restoration based solely on equal input hashes. The read-only blocker response writes no success audit or fake recheck event.
